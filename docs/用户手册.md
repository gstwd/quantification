## 1. 系统概览

### 1.1 定位与边界

> **系统只研究 A 股指数（宽基 / 行业 / 主题指数），仅支持日频，不研究 ETF。**

- 策略资产只能是你在「指数数据」页维护、且有实际 ETF 对应物的指数；申万行业和个股只作为因子的内部输入，
  不能成为策略资产或回测标的。
- 系统只输出研究与配置结果，不下单、不管理账户；回测与 AI 舆情都不是投资建议或实盘信号。
- 生命周期状态只能人工变更：系统不会自动调参、自动 promote 或自动上线策略。

### 1.2 核心概念

| 概念 | 说明 |
|------|------|
| **指数池** | 你维护的基准指数列表，是策略可选资产的全集 |
| **因子模板** | 一类计算逻辑（如 N 日收益），周期等参数可调；共 42 个，见 [6.2](#62-因子模板速查) |
| **因子别名** | 策略里给"模板 + 参数"起的名字，同一模板可用不同参数出现多次 |
| **策略** | 一份 JSON 配置，描述从因子值到持仓权重的完整逻辑 |
| **Regime** | 择时给出的市场状态：进攻（offensive）/ 中性（neutral）/ 防守（defensive） |
| **信号等级** | 每个资产的评分等级 HIGH / MID / LOW，见 [6.6](#66-信号等级速查) |
| **回测** | 在历史数据上运行策略；每次回测冻结策略配置快照，结果可审计、可对账 |
| **研究线** | 一条基线策略与其优化候选、稳健性变体、派生策略的集合；试验次数 N 与试验预算按研究线累计 |

### 1.3 决策管线

```
[可选] 择时 → 评分 → [可选] 过滤 → 排名 → 组合 → [可选] 风控 → 调仓
```

- 择时决定总仓位，评分 / 过滤 / 排名决定选哪些指数，组合决定权重，风控施加上限与止损，调仓决定什么时候执行。
- `portfolio` 缺省为等权；**没有择时模块时总仓位取 `portfolio.default_exposure`，缺省 0.5（半仓）**，想满仓需显式写 1.0。

### 1.4 研究期与验证期

| 区间 | 范围 | 用途 |
|------|------|------|
| 研究期 | 2016-01-01 ~ 2025-12-31 | 研究、调参、优化、稳健性检验 |
| 验证期 | 2026-01-01 起 | 只能用于验收否决与上线后监控 |

研究用途（`purpose=research`）的回测与优化不能越过研究期末端；验证（`validation`）与监控（`monitor`）用途可以使用
验证期数据，但会在策略上留下"验证期已消费"记录。看过验证期结果后再改策略，验证期证据就只能用于否决。

### 1.5 执行模型与记账口径

| 执行模型 | 含义 | 缺省场景 |
|---------|------|---------|
| `t_plus_1_close` | T 日收盘出信号，T+1 收盘成交 | 研究 CLI 与「新建回测」页的缺省 |
| `t_plus_1_open` | T 日收盘出信号，T+1 开盘成交（旧仓位吃隔夜段、新仓位吃日内段，两段复利） | API 缺省；存量回测缺执行模型时按此解释 |

记账口径 `drift_v1`：持仓在两次调仓之间随行情漂移，换手按漂移后的实际持仓计算；行情缺口期间收益记 0，缺口后补回
涨跌。缺少记账口径标记的存量回测按 `constant_mix_v0`（每日再平衡）标注，列表里显示"旧口径"徽标。
**执行模型、记账口径、日历来源不同的结果不可直接比较。**

### 1.6 毛收益与净收益

回测汇总指标是**毛收益**（不扣成本）。净口径在读取时按换手折算：`净收益 = 毛收益 − 单边换手率 × cost_bps / 100`，
`cost_bps` 是按单边换手折算的往返交易成本，缺省 0.5bp；回测详情另并列 0 / 0.5 / 5 / 10bp 四档成本阶梯。成本在创建回测时
固化，同一回测随时查看都得到同样的净指标。

## 2. 快速开始

1. **生成首次健康快照**：打开「数据管理」，点「检查全部质量」。后端启动时不做质量检查，首次部署时快照为空。
2. **同步数据**：点「同步全部数据」；之后系统每天北京时间 17:30 自动全局同步。
3. **维护指数池**：在「指数数据」页添加要研究的指数。
4. **建策略**：在「策略中心」新建策略（表单或 JSON），保存前系统会校验配置。
5. **跑回测**：在「回测中心」新建回测（用途选研究、执行模型保持研究默认），或用 CLI `backtest run`。
6. **读结果并核对**：看回测详情的指标、成本阶梯与告警；需要时用 `backtest verify <回测ID>` 独立对账。
7. **系统化研究**：登记假设 → 研究批量 / 稳健性 → 优化会话与 10 项验收，见 [第 5 章](#5-研究流程cli)。

## 3. 页面说明

页面按侧边栏顺序排列。

### 3.1 总览

**路径**：`/`

| 区域 | 内容 |
|------|------|
| 统计卡片 | 指数总数、启用策略、最新交易日、最近入库（北京时间） |
| 关注策略 | 星标策略的最新决策与仓位 |
| AI 舆情概览 | 当日市场综合研判与情绪摘要（无数据时隐藏） |
| 最近运行 | 最近的后台任务：Run ID、类型、策略、交易日、状态、开始时间 |

总览不展示数据质量，质量结论以「数据管理」页的健康快照为准。

### 3.2 策略中心

#### 策略列表

**路径**：`/strategies`

- **新建策略**：填写策略 ID、名称、描述、频率，选择策略类型（普通策略 / 组合策略），再用表单或 JSON 编写配置；保存前做结构与因子引用校验。
- **复制策略**：以现有策略的全部配置为起点另存一份。
- **星标关注**：星标策略出现在总览的「关注策略」。
- 卡片显示上线状态与健康等级（上线中的策略）。

#### 策略配置编辑

- **表单模式**：按模块（资产范围、择时、评分、过滤、排名、组合、风控、调仓）可视化编辑；因子下拉按模板的适用位置过滤，参数表单由模板参数定义驱动。
- **JSON 模式**：直接编辑完整配置，字段见 [第 4 章](#4-策略配置参考)。表单不渲染的字段（如 `regime_rules`、嵌套规则组）会原样保留。

#### 策略详情

**路径**：`/strategies/:strategyId`

- **配置详情**：各模块配置的可读展示；可编辑、删除。**上线中（LIVE）的策略配置已冻结**，不能直接编辑。上线 / 暂停中的策略、仍有成员的研究线根和已有试验的策略不能删除（删除会把试验从研究线 N 中拿走）。
- **研究数据瘦身**：先预览本策略研究线回测中可瘦身的数量与各类保护原因，确认后分批删除回测的逐指数明细，腾出数据库空间。回测汇总、逐日结果、稳健性批次、优化会话、研究台账与草稿策略全部保留，试验次数 N 与验收清单不变；被瘦身回测的收益归因不再可用，需要时用同一配置重跑。研究战役结束时会自动对战役期间的回测做同样的瘦身。
- **决策管线结果**：按指定交易日运行策略，显示排名、得分、类别与目标权重；「管线调试详情」列出每个因子的原始值、变换后值、权重与贡献，以及过滤规则的命中情况。
- **路径状态（回放重建）**：配置了排名缓冲、偏离调仓或风控叠加层的策略，决策依赖持仓与净值路径；系统从回放起点（上线策略取上线日，至少 60 天；其余约一年）回放到当日，页面显示回放起点、当日是否成交与原因。
- **稳健性验证**：列出该策略的稳健性批次（扫描 / 消融 / 池扰动），可查看各变体的 Δ夏普、Δ年化与统计结论。

#### 组合策略

新建时选择"组合策略"，按权重组合多个普通策略（成员各自保留择时、风控与调仓）。组合持仓按成员权重合成，成员之间方向相反的交易互相抵消。组合策略不能做稳健性扫描、优化会话与研究批量评估，请对成员分别执行。字段见 [4.10](#410-组合策略kindcomposite)。

### 3.3 生命周期

**路径**：`/lifecycle`

上线后的监控页。生命周期状态（LIVE / SUSPENDED / RETIRED）只由人工变更；健康等级（HEALTHY / WATCH / WARNING / CRITICAL）由体检自动计算。

- **标记上线**：选择策略与上线日期。上线时冻结配置快照与哈希，并用研究期回测生成该策略自己的研究期分布（1M / 3M / 6M / 12M / 24M 的超额与夏普分位、回撤分位）。
- **上线以来表现**：各窗口的超额收益、超额分位、夏普、夏普分位与期望差（实际表现相对研究期分布的偏离）。
- **评分因子 IC 诊断**与**组合分数 IC**：见下文。
- **体检历史 / 最近告警**：每次体检的健康等级、诊断与建议动作；定时体检的等级恶化或失败会写站内告警。
- **刷新**：手动执行一次体检；**状态变更**：暂停 / 恢复 / 退役。
- 每日数据同步完成后，系统自动刷新全部 LIVE 策略（可在配置中关闭），每条策略保留最近 5 条定时监控回测。

诊断阈值全部取自该策略自身的研究期分布：回撤分位 > 95 → WARNING；3M 超额分位连续 2 次 < 5 → WATCH；短中长期表现递减且组合分数 IC 显著衰减 → Alpha 衰减；回撤极端叠加衰减确认 → CRITICAL。

**组合分数 IC 与单因子 IC 的区别**：

- 组合分数 Rank IC 只比较**实际执行选股调仓日**的综合得分与其后一个调仓周期的指数收益（日 / 周 / 双周 / 月的前瞻期为 1 / 5 / 10 / 21 个交易日）。
- 横截面只包含当天**真正参与评分**的资产（通过候选池与过滤者），页面显示"评分 N / 标的 M"与覆盖率；当天评分资产不少于 5 个才产出有效 IC。
- 观测数约等于监控区间内的选股调仓次数（约 170 个交易日时：日频约 170、周频约 34、双周约 17、月频约 8）；判定衰减至少需要 24 个观测，前瞻窗口重叠时保守折算有效样本数。
- 观测不足时页面显示还差几个调仓日、约需几个月，并注明本次体检未采用 IC 证据——**"未确认衰减"不等于"信号仍然有效"**。
- 单因子 IC 只用于解释评分因子，不决定健康等级；过滤与择时因子不按横截面 Alpha 因子评估。单因子诊断取全交易日，与组合分数 IC 的日期集不同，数值不可直接比较。

### 3.4 研究看板

**路径**：`/research`（只读）

| 标签页 | 内容 |
|------|------|
| 研究线与台账 | 各研究线的试验次数 N 按来源拆分（稳健性批次、优化会话、研究批量、人工试验计入 N；派生因子诊断只登记、不计入）、试验预算、验证期是否已消费；假设树与结论 |
| 战役 | 研究战役的进度、各步骤角色（研究员 / 评审员）、结果、摘要与花费、停止原因 |
| 待确认的候选 | 已评估的优化候选：全区间毛口径指标对比、10 项验收清单与逐项证据、评审意见 |

### 3.5 AI 舆情与标签映射

- **AI 舆情**（`/ai-factors`）：新闻采集 → 情绪分析 → 标签分类 → 按标签聚合 → 可选的市场综合研判。它是独立的展示与研究辅助功能，**不是策略因子**，不能被策略引用。LLM 不可用时保留采集与聚合结果，研判显示为缺失。
- **标签映射**（`/keyword-tags`）：维护"关键词 → 资产标签"的映射，数据库中的映射优先于内置默认值。

### 3.6 因子中心

#### 因子列表

**路径**：`/factors`

每个卡片对应一个因子模板：模板 ID、名称、分类（量能 / 动量 / 波动率 / 估值 / 技术 / 宏观 / 市场 / 成分股 / 派生 / 价格 / 相对强度 / 市场宽度）、可调参标记与参数摘要、描述、所需数据、启用状态。可编辑名称、描述、分类与启用状态；参数范围由代码定义，页面不能修改。

#### 因子详情

**路径**：`/factors/:factorId`

模板带参数时，页面顶部提供参数表单，**所有标签页都按当前参数从原始数据现算**。

- **横截面快照**：某一天全部指数在该因子上的值，降序排列，附相对分布柱。
- **时间序列**：单个指数在日期范围内的因子值走势。
- **IC 分析（Rank IC）**：衡量因子的横截面预测能力，指标见 [6.5](#65-ic-分析指标速查)。
  - 横截面规模决定可信度：A 股指数池很小，指数越少相关系数取值越粗。**横截面少于 20 个指数的交易日不产出有效 IC**，页面会提示并给出区间内观测到的最大指数数量；`min_cross_section_n` 可放宽门槛，最低为 5（接口强制）。
  - 前瞻窗口大于 1 日时相邻观测重叠，系统按有效样本数（数据点 / 前瞻天数）计算 t 统计量。
  - 柱状图：绿色 = IC > 0，红色 = IC < 0；悬浮可见当日横截面指数数——柱子高但指数少属于小样本噪声。
- **因子相关性矩阵**：同一天各因子之间的 Spearman 秩相关热力图。每对因子用各自共同覆盖的指数计算，样本不足（默认 < 20）或无法定义时格子为空，表示"无法判断"而非"不相关"。|r| > 0.7 高度冗余；|r| < 0.3 互补性好。

### 3.7 RRG / 扩散研究

**路径**：`/tools/rrg-lab`

申万行业 RRG 四象限与历史轨迹、扩散时序 / 排名 / 覆盖度的研究调试台。只做研究展示：不创建策略、不写因子值、不触发回测；查询参数与数据上限由服务端校验并提示。研究结论通过 `rrg_industry_match_score`、`index_diffusion_ratio` 等指数级因子进入策略。

### 3.8 量价 / 择时研究

**路径**：`/tools/signal-lab`（CLI：`research signal-lab`）

选择日期范围、指数与信号（因子 + 参数，或某个策略的择时口径与代理指数），观察信号与未来收益的关系。择时综合分与回测是同一实现，可直接载入任一策略的 timing 配置。只读，不产生回测。

### 3.9 运行记录

**路径**：`/runs`

后台任务的执行历史：Run ID、类型、策略、交易日、状态、总耗时（含排队）、创建时间；展开可看全局同步的逐数据集子项。

| 运行类型 | 说明 | 可重试 |
|---------|------|-------|
| 全局数据同步（`data_sync_all`） | 每日定时或手动触发，覆盖全部受管数据集 | 是 |
| 数据维护（`data_manage_operation`） | 单数据集 / 单分区的检查、补最新、修复缺口、全量重拉 | 是 |
| 策略运行（`strategy_run`） | 策略的实时决策 | 是 |
| AI 舆情分析（`ai_analysis`） | AI 舆情链路 | 是 |

标注"已下线"的类型只用于展示存量记录，不能重试。队列概况可用 CLI `queue stats` / `queue jobs` 查看。

### 3.10 数据管理

**路径**：`/data-management`

以"数据集 → 分区"两级视图维护全部非新闻外部数据（交易日历、指数日线 / 估值 / 成分、宏观、日频市场指标、申万行业、个股），是数据质量的唯一入口。

| 区域 | 内容 |
|------|------|
| 页头 | 数据集总数、最近一次检查时间；「检查全部质量」「同步全部数据」 |
| 状态汇总 | 全部 / 健康 / 需关注 / 异常 / 待检查 / 不支持 六类计数，点击筛选 |
| 数据集列表 | 健康状态、频率、分区单位、最新数据日期与问题规模 |
| 数据集摘要 | 数据范围、目标日期、记录数、缺口 / 异常、最近实际来源、来源策略、最近检查与同步时间、检查定义与缺口样例 |
| 分区明细 | 按分区分页展示状态、实际 ~ 目标日期、记录数、缺口、异常与问题，支持关键字与状态筛选 |

**健康状态**：正常（满足时效与字段规则）/ 需关注（日期落后、连续性缺口或告警规则命中）/ 异常（无数据、字段非法或最近维护失败）/ 尚未检查 / 上游不支持（如没有估值覆盖的指数）。

**维护操作**：

- **检查**：只扫描并刷新健康快照，不改动数据。
- **补最新**：补齐到目标日期；低频数据集（成分 / 目录）在 7 天刷新周期内由全局同步自动跳过，手动补最新会强制拉取。
- **修复缺口**：重新扫描完整缺口后定向补数，不会由定时任务自动执行。
- **全量重拉**：抓取校验通过后替换现有数据，需输入 `REBUILD:<数据集>:<分区或 ALL>` 确认令牌；耗时长，不作为常规刷新手段。

**规则要点**：

- 健康快照只在手动维护操作或每日 17:30 全局同步完成后更新，后端启动不会生成。
- 指数 / 行业日线：单日涨跌幅超过 30% 或 ≤ −99.99% 记为异常，15%~30% 记为告警（真实大涨大跌需人工确认）；落在非交易日的行情记为异常，「修复缺口」会删除这些行；成交量为 0 只作提示。
- 上游没有的日期：「修复缺口」确认所有来源都请求成功且都没有该日期后登记为上游缺失，不计入缺口、不影响状态，只在问题栏提示「上游缺失 N 天（仅提示）」。
- 停牌个股：「修复缺口」也会复验个股最新日期之后的交易日；全市场数据里确认都没有该股时，不再显示「数据已过期」，只提示「最新日期后停牌或上游无数据 N 天」。复牌后的新数据由日常同步写入。
- 上游只提供收盘价的历史日期：「修复缺口」确认所有来源都只有收盘价后登记为"上游仅收盘价"，这些行只作提示、不影响状态；回测仍会剔除缺开盘价（T+1 开盘执行）或缺最高 / 最低价（ATR、唐奇安、RSRS 等因子）的日期，并在回测警告中列出。
- 数据来源按数据集区分：指数、日历、宏观与市场指标 Tushare 优先、其他来源兜底；个股数据只取自 Tushare；指数估值以中证官网为主来源，Tushare 只在其不可用时为沪深300、上证50、中证500 兜底。
- 指数行情、估值、宏观页面在没有数据时不会在后台自动补数，请在本页执行同步。
- 深链 `?dataset=<数据集>&partition=<分区>` 直接打开指定数据集与分区。

#### 新建回测

**路径**：`/backtests/new`

| 字段 | 可选值 |
|------|--------|

| 数据质量 | 缺口汇总提示（默认）/ 缺口逐指数提示（只影响提示详细程度，候选池相同） |
| 回测用途 | 研究期研究（2016-01-01 ~ 2025-12-31）/ 验证期验收（2026-01-01 起，留痕）/ 上线后监控（留痕） |

#### 回测详情

**路径**：`/backtests/:backtestId`

- **绩效指标**：累计 / 年化收益、最大回撤与持续天数、夏普、卡玛、索提诺、胜率（只统计持仓日）、信号准确率、盈亏比、交易日与持仓日、基准收益、超额收益、Alpha / Beta / 信息比率，见 [6.1](#61-回测绩效指标速查)。
- **分年度绩效表**：按自然年切分收益、夏普、索提诺与最大回撤。
- **稳健性指标**：收益集中度（最大年度占比、剔除最好年份后的年化）、三段一致性、夏普为正年份占比、期末回撤分位、最长水下天数。
- **成本阶梯**：0 / 0.5 / 5 / 10bp 下的净累计收益、净年化、净夏普、净超额与年化成本拖累。
- **收益归因**：全区间与分年度的 组合 / 基准 / 择时（(总仓位 − 1) × 基准收益）/ 选择（Σ 权重 × (资产 − 基准)）/ 残差，满足 组合 − 基准 = 择时 + 选择 + 残差；另列资产贡献前 10。T+1 开盘执行的调仓日按两段复利，分解标注为近似。
- **择时统计**（配置择时时）：各 regime 天数、时间占比、平均仓位、组合与基准的日均和年化收益；配置多档仓位时另按档位分组。
- **有效候选池时间线**：逐日实际可交易的指数数量与剔除原因（行情缺失、决策所需因子缺失等）。
- **图表**：权益曲线（可叠加基准）、回撤曲线、滚动夏普 / 索提诺（252 日窗口）、仓位堆叠图、择时状态时间线。
- **告警**：数据缺口、预热期、择时降级、候选池收缩、基准缺失等结构化提示。

#### 策略对比

**路径**：`/backtests/comparison/new`、`/backtests/comparison/:comparisonId`

同时回测策略 A 与策略 B（各自的标的范围、相同区间、执行模型、数据质量与基准），并排比较指标与曲线。

### 3.13 站内告警

侧边栏的铃铛显示未读告警数（每分钟刷新）。三类告警：LIVE 策略健康等级恶化、定时体检失败、每日数据同步有数据集失败；同一事件同一天只记一条。告警只做提醒，不会调参、改状态或给出交易信号。

## 4. 策略配置参考

本章是策略配置字段的唯一参考。完整字段、缺省值与校验规则以 `apps/api/src/quant_etf_api/engine/config.py` 为准；保存前可用 `strategy validate` 或策略编辑器校验。

### 4.1 整体结构

```json
{
  "strategy_id": "英文唯一标识",
  "display_name": "策略名称",
  "version": "1.0.0",
  "description": "说明",
  "frequency": "daily",
  "index_codes": ["000300", "000905"],
  "factor_aliases": { "别名": { "template_id": "模板 ID", "params": { "period": 20 } } },
  "timing": {},
  "score": {},
  "filters": {},
  "rank": {},
  "portfolio": {},
  "risk": {},
  "rebalance": {},
  "regime_rules": {}
}
```

- 只有 `score` 必填；`rank` 缺省为全部入选、`portfolio` 缺省为等权；其余模块可选。
- `index_codes` 限定策略资产范围（空表示全部指数池），会覆盖回测请求里的标的范围。
- 顶层 `frequency` 只是标注字段，不控制调仓；调仓由 `rebalance` 决定。

### 4.2 因子别名（factor_aliases）

| 字段 | 说明 |
|------|------|
| 别名（键） | 策略内唯一的引用名，评分 / 择时 / 过滤 / 排名引用的就是它 |
| `template_id` | 因子模板 ID（[6.2](#62-因子模板速查)） |
| `params` | 模板参数覆盖；未给的取默认值，未知参数或越界值在保存前被拒绝 |

引用名在 `factor_aliases` 中声明就用声明的模板与参数，否则按模板 ID + 默认参数解释。同一模板配不同参数必须通过别名区分；同模板同参数只计算一次。

**派生因子**：`{"template_id": "expr", "params": {"expr": "ts_zscore(mom20, 60)"}}` 在已有别名或模板上做四则运算与函数组合，支持 `abs / min / max / log / sqrt / sign` 与时序函数 `delay(x, n)`、`delta(x, n)`、`ts_mean / ts_std / ts_zscore / ts_rank(x, n)`（窗口 ≤ 250），不支持截面函数。派生因子进入研究批量或优化候选前，必须先做 `research factor-ic` 或 `research buckets` 诊断。

### 4.3 评分（score，必填）

| 字段 | 缺省 | 说明 |
|------|------|------|
| `factors` | — | 因子权重，键为引用名，正 = 越大越好，负 = 越小越好 |
| `transforms` | {} | 因子变换（[6.3](#63-变换函数速查)），把原值映射到 0-100 |
| `scoring_mode` | absolute | absolute：按 `Σ(|w| × d) / Σ|w|` 合成，负权重时 d = 100 − 变换值；rank：横截面平均秩百分位；zscore：横截面标准分 |
| `missing_factor_strategy` | ignore | ignore：忽略并重新归一化；zero：按最差处理；exclude：评分前剔除该资产 |

### 4.4 择时（timing，可选）

| 字段 | 缺省 | 说明 |
|------|------|------|
| `combine` | weighted | weighted：因子加权综合分过阈值；rules：进攻 / 防守规则组 |
| `factors` / `transforms` | {} | 加权模式的因子权重与变换；原值不在 0-100 的因子（收益率、RSRS、量比等）必须配变换，RSI、市场宽度、估值百分位等可不配 |
| `thresholds.offensive` / `.defensive` | 65 / 35 | 加权模式：综合分 ≥ 进攻阈值为进攻，≤ 防守阈值为防守，其余中性 |
| `rules.defensive` / `rules.offensive` | — | 规则模式：结构同过滤配置，比较因子原值；防守优先，都不满足为中性 |
| `proxy_index_codes` | ["000300"] | 择时代理：按顺序取第一个让全部择时因子都有值的代理，都不能全覆盖时逐因子回退 |
| `factor_proxies` | {} | 按因子指定代理（如价量共振看中证1000、动量看沪深300） |
| `on_degraded` | neutral | 择时因子全部缺失时：neutral / defensive / hold_previous（沿用上一决策日） |
| `state.hysteresis` | 0 | 滞回带（加权模式）：已在进攻时综合分不低于"进攻阈值 − 滞回带"就保持，防守对称 |
| `state.hold_on_neutral` | false | 无信号（中性）时维持前一 regime |
| `state.confirm_days` | 1 | 新 regime 连续出现多少个决策日才切换 |
| `state.min_hold_days` | 0 | 切换后至少持有的决策日数 |
| `state.max_exposure_step` | null | 档位决定的目标仓位每个决策日最多变动多少（如 0.25 即每次最多一档） |
| `tiers` | [] | 多档仓位，按顺序首个命中的档位决定总仓位，见下 |
| `tier_base_exposure` | null | 动态档位（hold / exposure_delta）在没有上一仓位时的起点；含动态档位时必填 |
| `exposure_caps` | [] | 条件仓位上限 `[{label, max_exposure, logic, rules}]`：规则满足时封顶总仓位，多条命中取最小值，施加在档位 / regime 仓位之后、风控之前 |

**多档仓位 `tiers[]`**：

- 命中条件：加权模式用 `min_score`（综合分 ≥ 该值命中，各档从高到低排列，regime 仍按阈值）；规则模式用 `logic + rules`（结构同过滤）并声明命中时的 `regime`，与 `rules.offensive / defensive` 互斥。
- 仓位方式三选一：`exposure`（固定仓位）、`hold: true`（维持上一仓位）、`exposure_delta`（相对上一仓位增减，限制在 `min_exposure` ~ `max_exposure`）。
- 都未命中或择时降级时按 regime 仓位表（`portfolio.timing_exposure`）。

状态层按"滞回 → 无信号维持 → 确认 → 最短持有"的顺序施加，缺省时不改变任何判定。启用多档仓位时，状态层维持前一 regime 的日子同时沿用上一档位；同一 regime 内换档当日生效。实时决策回放最近 250 个交易日重建状态，与回测同一实现。

### 4.5 过滤（filters，可选）

| 字段 | 缺省 | 说明 |
|------|------|------|
| `logic` | AND | 多规则逻辑：AND / OR |
| `rules[].factor` | — | 因子引用名 |
| `rules[].op` | — | gt / lt / gte / lte / eq / neq / between |
| `rules[].value` | — | 比较值；between 时为 [下限, 上限] |
| `rules[].compare_to` | null | 与另一个因子比较（如收盘价 > 均线），此时不写 value |
| `rules[].missing_strategy` | fail | 因子缺失时：fail（不通过）/ pass（通过）/ exclude（剔除资产） |
| `groups` | [] | 嵌套子规则组（最多 3 层），用于表达 (A 且 B) 或 C |

### 4.6 排名（rank）

| 字段 | 缺省 | 说明 |
|------|------|------|
| `sort_by` | score | 只支持按综合得分排序；要按某个因子排序请把它放进 `score.factors` |
| `order` | desc | desc / asc |
| `top_n` / `bottom_n` | null | 取前 N / 后 N 名（二选一），null 为全部 |
| `buffer_n` | null | 排名缓冲带（需 top_n）：已持有资产排名仍在 top_n + buffer_n 内时保留，减少名次边缘的来回换仓 |
| `momentum_factor` / `valuation_factor` | null | 只用于展示动量 / 估值子排名，不参与排序 |

得分相同按指数代码升序。

### 4.7 组合（portfolio）

| 字段 | 缺省 | 说明 |
|------|------|------|
| `method` | equal_weight | equal_weight / score_weight / winner_take_all / inverse_vol（波动率倒数加权）/ risk_parity（风险平价） |
| `default_exposure` | 0.5 | 无择时时的总仓位 |
| `timing_exposure` | 见下 | 各 regime 的总仓位；有择时但不配置时用默认三档（进攻 0.8 / 中性 0.5 / 防守 0.2）；只写部分 regime 时缺的档回退到 `default_exposure` 并给出提示，建议三档写全 |
| `vol_factor` | null | inverse_vol 必填：波动率因子引用，该因子缺失的资产不参与决策 |
| `cov_window` | 60 | risk_parity 的协方差窗口（20-250 个交易日）；共同有效天数不足一半时退回等权 |

### 4.8 风控（risk，可选）

| 字段 | 缺省 | 说明 |
|------|------|------|
| `max_asset_weight` | 0.30 | 单资产仓位上限 |
| `max_portfolio_exposure` | 1.0 | 组合总仓位上限；不能大于 1 − `min_cash_ratio` |
| `min_cash_ratio` | 0.0 | 最低现金比例 |
| `vol_target` | null | 波动率目标 `{target, window=60, floor=0}`：估算组合年化波动超过 target 时等比降仓（只降不加） |
| `drawdown_stop` | null | 组合回撤止损 `{threshold, exposure=0, cooldown_days=20}`：净值回撤达到 threshold 后总仓位压到 exposure，冷却期满恢复 |
| `trailing_stop` | null | 单资产移动止损 `{threshold, cooldown_days=20}`：持仓自入场高点回撤达到 threshold 即清出，冷却期内不再入选 |

后三项依赖策略走到今天的路径：新触发的止损在下一决策日强制成交，不等调仓日；实时决策回放一段历史重建状态（见 [3.2 策略详情](#策略详情)）。

### 4.9 调仓（rebalance，可选）

不配置时每个交易日都调仓。配置后两条腿各有一份日程：

- **选股腿 `selection`**：重建组合成分与权重；
- **风险腿 `risk`**：只把现有成分等比缩放到择时目标总仓位，不引入新成分。

| 字段 | 缺省 | 说明 |
|------|------|------|
| `selection` / `risk` | `{"frequency": "daily"}` | 只给一条腿时，另一条按相同日程补齐 |
| `*.frequency` | daily | daily / weekly / biweekly / monthly |
| `*.day_of_week` | 周五 | 周度 / 双周调仓日，0 = 周一 … 4 = 周五 |
| `*.week_parity` | — | 双周必填：odd / even，以 2016-01-04 所在周为第 1 周连续计数 |
| `*.day_of_month` | 1 | 月度调仓日（1-31，建议 ≤ 28），超出当月天数按最后一日 |
| `band.min_turnover` | null | 调仓日所需单边换手低于该值时跳过本次调仓（止损强制成交不跳过） |
| `band.max_drift` | null | 非调仓日任一资产实际权重偏离最近一次目标超过该值时回到该目标（不重新选股） |

- 直接在 `rebalance` 下写 `frequency` / `day_of_week` / `day_of_month` 的平铺写法按两腿同频解释。
- **两腿同频**时，每个调仓日按"新成分 + 择时目标仓位"重建；**两腿异频**时，选股腿日只换成分、维持当前总仓位，总仓位只在风险腿日按择时目标调整；空仓时风险腿不会建仓。
- 未配置择时时，风险腿只会把仓位缩放到 `portfolio.default_exposure`。
- **顺延**：调仓日 = 目标日（含）之后的第一个交易日，可跨周、跨月顺延；同一周期内至多调仓一次，双周未命中的周期不会补触发。

### 4.10 组合策略（kind=composite）

| 字段 | 缺省 | 说明 |
|------|------|------|
| `kind` | — | 固定为 `composite` |
| `members` | — | `[{strategy_id, weight}]`，1-10 个普通策略 |
| `cash_weight` | 0.0 | 现金权重；成员权重 + 现金权重 = 1 |
| `rebalance` | `{"frequency": "daily"}` | 成员权重调回目标的日程（daily / weekly / biweekly / monthly） |

回测时成员配置随组合一起冻结；换手与成本按合成后的持仓计算。

### 4.11 按 regime 覆盖（regime_rules，可选）

## 5. 研究流程（CLI）

研究动作在 CLI 中执行（`cd apps/api` 后 `python -m quant_etf_api.cli ...`），完整参数以 `--help` 为准。研究类命令的执行模型缺省都是 `t_plus_1_close`，日期缺省落在研究期内。

### 5.1 回测与核对

```bash
python -m quant_etf_api.cli backtest run --strategy <id>                 # 研究回测（可加 --start/--end、--benchmark-mix 000300:0.6）
python -m quant_etf_api.cli backtest show <id> --cost-ladder 0,5,10,20   # 详情、口径指纹、临时成本档
python -m quant_etf_api.cli backtest pool <id>                           # 有效候选池时间线
python -m quant_etf_api.cli backtest verify <id>                         # 独立对账（只读）
```

`backtest verify` 不复用回测执行器的代码，按记账规格从原始行情独立复算逐日收益、换手、持仓连续性、累计收益、回撤、基准与汇总指标，有差异时退出码为 1。差异可能来自实现缺陷，也可能来自回测之后行情被上游修订：用同一快照重跑后再对账即可区分。只在 `active_days` / `win_rate_pct` 上有差异的存量回测，重跑即可修正。

### 5.2 只读诊断

```bash
python -m quant_etf_api.cli research factor-ic --factor return --params '{"period": 20}'  # 单因子 IC / ICIR
python -m quant_etf_api.cli research buckets ...                                       # 分组收益
python -m quant_etf_api.cli research signal-lab ...                                    # 量价 / 择时信号研究
```

诊断不产生回测；派生因子的诊断记录是它进入研究批量与优化的前提。

### 5.3 假设、台账与研究线

```bash
python -m quant_etf_api.cli research hypothesis add --statement "..." --category timing --criteria "..." --strategy <id>
python -m quant_etf_api.cli research ledger --strategy <id>
python -m quant_etf_api.cli strategy create --id <新ID> --name "..." --file cfg.json --draft --lineage <原策略ID>
```

- **先登记判定标准再检验**；假设关闭后不再接收试验。
- 试验次数 N = 稳健性批次变体 + 已评估优化会话 + 研究批量变体（每次运行自动记录）+ 人工 / 补录试验，按研究线累计（派生因子诊断只登记、不计入 N）；每条研究线有试验预算（缺省 100），用尽后产生试验的命令拒绝执行，需 `--over-budget` 给出理由。
- 派生新策略必须用 `--lineage` 归入原研究线，不能用另建策略的方式重置 N。

### 5.4 研究批量与稳健性

```bash
python -m quant_etf_api.cli research batch --strategy <id> --variants variants.json --summary
python -m quant_etf_api.cli robustness scan   --strategy <id> --preset quick --sync
python -m quant_etf_api.cli robustness ablate --strategy <id> --sync
python -m quant_etf_api.cli robustness pool   --strategy <id> --sync
python -m quant_etf_api.cli robustness stats  <robustness_id>
```

- `research batch` 走同一执行路径但不落库，用于快速筛掉没价值的想法；`--timing-attribution` 追加"关闭择时"对照，回答择时是否有净贡献。报告与验收数字必须来自落库回测。
- `robustness scan` 对配置数值做 ±1 档扰动：单个旋钮的全部变体 |Δ夏普| ≤ 0.1 视为处于参数平台，两侧都超过容差视为方向反转；`ablate` 逐个移除评分因子与过滤条件；`pool` 做子池、剔除常持指数、剔除后上市指数等资产池扰动；`stats` 给出 CSCV-PBO 与 Deflated Sharpe。
- 不带 `--sync` 时批次只入队，由后台 worker 执行；`--sync --workers N` 在本机并行。

### 5.5 优化会话与 10 项验收

```bash
python -m quant_etf_api.cli optimization start --strategy <基线ID> --candidate-file cand.json --hypothesis-id <hid>
python -m quant_etf_api.cli optimization evaluate <oid>
python -m quant_etf_api.cli optimization show <oid>              # 10 项验收清单与逐项证据
python -m quant_etf_api.cli optimization finish <oid> --verdict accept --strict [--promote]
```

`optimization start` 缺省覆盖整个研究期。`--strict` 要求 10 项全部通过：

1. 验证窗平均夏普 ≥ 基线；
2. 平均最大回撤劣化 ≤ 2pct；
3. 夏普胜出折数 ≥ 50%；
4. 验证窗平均累计收益 ≥ 基线；
5. 净成本口径验证窗平均夏普 ≥ 基线；
6. 参数邻域无方向反转且处于平台（需匹配会话配置哈希的 `robustness scan`）；
7. 剔除最好折后候选夏普仍不低于基线；
8. 候选相对基线的逐日超额净收益的 Deflated Sharpe ≥ 0.95（N 取研究线累计试验数）；
9. 剔除候选领先最多的一年后年均净夏普仍 ≥ 基线，且胜出年数不少于一半；
10. 候选与基线的差异事件至少 8 段、40 天。

`--no-strict` 接受必须给出理由并写入研究台账。`--promote` 把候选配置提升为新版本，由人工决定执行；LIVE 策略的配置不能直接替换。

### 5.6 上线与监控

```bash
python -m quant_etf_api.cli lifecycle online <id> --live-at 2026-01-05 --note "..."
python -m quant_etf_api.cli lifecycle refresh <id>
python -m quant_etf_api.cli lifecycle status <id> --set SUSPENDED --note "..."
```

### 5.7 研究战役（自动研究循环）

```bash
python -m quant_etf_api.cli research campaign start --strategy <id> --objective "..." --max-trials 30
python -m quant_etf_api.cli research campaign run <campaign_id>      # headless 驱动器
python -m quant_etf_api.cli research campaign status <campaign_id>
python -m quant_etf_api.cli research campaign stop <campaign_id> --reason "..."
```

战役交替执行研究员与评审员步骤，由平台判定停止条件（试验增量、研究线预算、时长、轮数、连续否决、连续失败）并拦截越权命令：战役内不能 promote、不能放宽验收、不能消费验证期、不能修改基线或启用策略。驱动方式有两种：`campaign run` 启动 headless Claude Code 会话；或在 Claude Code 桌面会话里编排（`begin-step` / `finalize-step`，流程见 `.claude/skills/research-campaign/`）。战役内接受候选需评审员推荐且严格通过全部验收项，promote 与上线由人工执行。

### 6.5 IC 分析指标速查

| 指标 | 含义 | 判读 |
|------|------|------|
| ic_mean | Rank IC 平均值 | 结合 t 统计量与横截面指数数判读 |
| ic_std | IC 标准差 | 越小越稳定；小横截面会放大该值 |
| ic_ir | IC 均值 / IC 标准差（未年化） | 衡量稳定性，不衡量显著性 |
| t_stat | IC_IR × √有效样本数 | \|t\| > 2 才算显著非零 |
| ic_positive_ratio | IC 为正的交易日比例 | > 50% |
| cross_section_n_avg | 平均横截面指数数（另有 min / max） | 越大越可靠 |
| cross_section_n_required | 有效 IC 所需的最小横截面数 | 默认 20，可放宽到不低于 5 |
| excluded_low_n_days | 因横截面不足被排除的交易日数 | > 0 时页面提示 |
| dropped_no_forward_days | 缺前瞻行情被丢弃的交易日数 | 区间末端属正常 |
| effective_n | 有效样本数 = 数据点 / 前瞻天数 | 前瞻窗口重叠时的真实样本量 |
| insufficient_reason | 未产出有效 IC 的原因 | 非空说明该区间无法计算 IC |

## 7. 回测结果解读

### 7.1 权益曲线与回撤

- 策略线在基准线上方且走势平滑 → 跑赢且稳健；大幅波动 → 关注回撤。
- 回撤在 −10% 以内为低风险，−10% ~ −25% 中等，超过 −25% 高风险；回撤恢复得快说明策略韧性好。

### 7.2 仓位与择时

- 权重切换平缓 → 换手低、成本低；快速切换 → 注意成本阶梯里的净收益。
- 现金比例大 → 策略偏防守；注意无择时策略缺省只有半仓（`default_exposure=0.5`）。
- 防守 regime 占比过高可能错失机会，进攻占比过高熊市回撤大；结合择时统计里各 regime 的组合与基准收益判断择时是否有效，净贡献用 `research batch --timing-attribution` 回答。

### 7.3 稳健性与成本

- 收益集中度高（最大年度占比大、剔除最好年份后年化明显下降）说明收益依赖少数年份。
- 三段一致性与夏普为正年份占比反映跨阶段的稳定性。
- 成本阶梯中 5bp、10bp 下净夏普明显下降，说明策略对交易成本敏感。

### 7.4 指标组合判读

| 如果… | 则… |
|-------|-----|
| 夏普高 + 回撤低 | 风险收益比好 |
| 夏普高 + 回撤高 | 高收益伴随高风险 |
| 胜率高 + 盈亏比高但夏普低 | 可能有异常值影响 |
| Alpha 显著 > 0 | 有独立于市场的超额收益 |
| Beta 接近 1 | 基本跟随市场 |
| 信号准确率 ≈ 基准上涨日占比 | 选股没有超出市场本身的上涨概率 |

## 8. 常见问题

### Q1：为什么有些指数的 PE / PB 分位为空？

估值源覆盖有限（见 [3.11](#指数数据)）：中证系指数只有 PE 及其分位，PB 一般为空；创业板50、深证系等没有任何估值源的指数显示"—"，健康快照标为"上游不支持"。

### Q2：回测详情的部分指标显示"—"？

- 回测仍在执行（pending / running），完成后自动刷新；
- 未启用基准，基准相关指标为"—"；
- 盈亏比为"—"：回测期间没有亏损日。

### Q3：因子 IC_IR 很低怎么办？

1. **先看横截面与 t 统计量**：指数池小时 IC 噪声极大，|t| < 2 说明 IC 与噪声无法区分，此时调参没有意义；
2. IC 均值低：因子预测力不足，换因子或换参数；
3. IC 标准差大：因子分阶段有效，考虑与择时或其他因子组合；
4. 数据点少于 30：延长区间。

反过来，IC_IR 高也不等于可用：单日高 IC 往往来自横截面只有三五个指数的交易日，系统已把这类观测排除并提示。

### Q4：数据管理页显示"需关注"或"异常"怎么办？

先「检查全部质量」确认范围，再对目标数据集或分区执行「补最新」或「修复缺口」；「全量重拉」只在数据整体错误时使用。仍然缺失时看数据集摘要里的最近实际来源与错误信息：上游暂时不可用时稍后重试；个股数据需要配置 Tushare Token。

### Q5：怎样判断一个策略是否值得上线？

不要用单一阈值（如"夏普 > 1"）判断。系统化的路径是：

1. 研究期内完成假设登记、研究批量与稳健性检验（参数平台、消融、池扰动、PBO / DSR）；
2. 以优化会话对比基线，**严格通过 10 项验收**（[5.5](#55-优化会话与-10-项验收)），落库回测用 `backtest verify` 对账；
3. 用验证期回测做最后一次否决检验（会留痕）；
4. 人工 promote 并在「生命周期」页标记上线，之后按自身研究期分布持续体检。

### Q6：变换函数怎么选？

| 因子类型 | 推荐变换 | 原因 |
|---------|---------|------|
| 收益率（return） | momentum_score | 分段映射为合理得分 |
| 估值分位（pe / pb_percentile） | invert_percentile（权重为正） | 低分位 = 便宜 = 高分；不要再配负权重，否则两次反转相互抵消 |
| 量比（volume_ratio） | volume_score | 适中放量得分最高 |
| 波动率（volatility） | `linear(lo,hi)` 配负权重 | 原值不是 0-100，先线性映射；负权重表示低波动高分 |
| 均线乖离（ma_deviation） | trend_score | 价格相对均线的位置映射 |
| RSI、市场宽度、估值百分位 | 不配或 clamp_0_100 | 原值已在 0-100 |
