# A 股指数量化系统策略架构

本文档描述当前运行架构与口径；策略研究方法、参数高原和生命周期原则分别见链接文档，不在此重复定义。

## 边界与资产域

- 系统研究 A 股指数，频率为日频；不提供 ETF、个股交易或交易执行能力。
- 策略资产只能来自 `benchmark_index`，并且应有市场中实际 ETF 对应物。
- 申万行业和个股数据仅能作为 `rrg_industry_match_score`、`index_diffusion_ratio` 等指数级因子的内部输入；它们不能进入策略 `index_codes` 或作为回测标的。

## 执行管线

```text
StrategyEngine.run(config, context)
  → [可选] Timing
  → Score
  → [可选] Filter
  → Rank
  → [可选] Portfolio
  → [可选] Risk
  → EngineResult
```

`RebalanceScheduler` 在回测中决定何时实际重建成分和调整风险仓位；非执行日沿用已有持仓。策略配置必须包含 `portfolio` 才能创建回测。

| 组件 | 当前职责 |
| --- | --- |
| Timing | 根据市场级因子生成 offensive / neutral / defensive regime。 |
| Score | absolute 按 `Σ(|w| × d) / Σ|w|` 逐资产评分，`d = transform(value)`，负权重时 `d = 100 − transform(value)`（反向）；rank/zscore 先对每个因子做横截面标准化（rank 平均秩百分位、zscore 标准分），再按权重合成并对综合值做 0-100 映射。缺失策略 `zero` 表示"按最差处理"：absolute 下该因子记 0 分，横截面模式下比有值资产中方向最差者再差一档（rank 一个名次、zscore 一个标准差）。 |
| Filter | 支持 `gt/lt/gte/lte/eq/neq/between`、AND/OR 和跨因子比较。 |
| Rank | 固定按综合得分排序并截取 TopN/BottomN，得分相同按指数代码升序；`momentum_factor` / `valuation_factor` 只产出展示用子排名（估值按原值升序）。 |
| Portfolio | equal_weight、score_weight 或 winner_take_all；目标总仓位由 `resolve_target_exposure()` 统一决定，无择时时用 `default_exposure`。 |
| Risk | 限制单资产权重、总仓位和最低现金比例。引擎另输出 `timing_target_exposure`（regime 仓位经组合级风控裁剪），与当日选股结果无关。 |

配置中的枚举字段（评分模式、缺失策略、过滤操作符与逻辑、排序方向、权重方法、regime 名称）由 schema 严格约束，写错在解析期即被拒绝；`regime_rules` 覆盖块与顶层执行同一套跨字段校验。

**评分前剔除（实时与回测共用）**：引擎在 regime 覆盖之后、评分之前，按生效配置剔除"决策必需因子"缺失的资产——评分 `missing_factor_strategy=exclude` 的评分因子，以及 AND 逻辑下 `missing_strategy` 为 fail/exclude 的过滤因子；市场级模板引用豁免。ignore / zero / pass 与 OR 逻辑下的缺失由各模块按原语义处理。剔除明细写入 `EngineResult.excluded`，实时返回 `CANDIDATE_EXCLUDED` 提示，回测合并进候选池时间线（原因码 `MISSING_FACTOR`）。回测 `_build_candidate_pool` 只判定行情可执行性（收盘、高低价、次日行情、开盘价）。

## 参数化因子现算

策略因子引用可以直接是模板 ID，也可在 `factor_aliases` 中声明别名、模板和参数：

```json
{
  "score": {"factors": {"short_mom": 0.3, "long_mom": 0.7}},
  "factor_aliases": {
    "short_mom": {"template_id": "return", "params": {"period": 5}},
    "long_mom": {"template_id": "return", "params": {"period": 20}}
  }
}
```

`FactorProvider` 收集引用并由 `FactorTemplateRegistry` 解析为规范化实例。实时分配通过 `load_asset_factor_matrix()` 和 `load_market_factors()` 从原始数据计算当前交易日；回测通过 `precompute_backtest_factors()` 使用预加载数据批量计算。`ContextBuilder` 只读地将这些结果组装为 `EngineContext`。

因子值不持久化，也没有因子值补算任务。`factor_definition` 保存的是模板目录；原始数据不足或计算失败会作为结构化缺失结果返回。详见[参数化因子与参数高原治理升级方案](参数化因子与参数高原治理升级方案.md)。

## 回测与可比性

`BacktestService` 在创建时快照策略配置和哈希，执行时优先使用快照；快照存在但解析失败时回测直接失败，不回退到当前配置（只有无快照的旧回测才读取当前配置）。每个结果记录候选池、调仓日历来源、换手模型、数据质量口径、基准和执行模型。

T+1 收盘执行中，昨日指令先在今日收盘成交，今日新指令的双腿合成以该成交后的持仓为基准。仅风险腿到期时只缩放已成交成分，不恢复成交前成分；明确清仓的空字典与没有待执行指令的 `None` 必须区分。仅选择腿到期时也维持今日成交后的总仓位。

双腿单独到期的合成（`compose_two_leg_positions`）：仅风险腿到期时按 `timing_target_exposure` 缩放现有成分——当日过滤后无入选资产或入选资产被单资产上限裁剪，都不会让风险腿清仓或压低仓位；仅选股腿或仅风险腿到期时，缩放后的持仓都按单资产上限裁剪，超出部分留作现金。两腿同日到期时直接采用引擎目标，与改造前口径一致。实时星标摘要用 `plan_mode`（full / selection_only / risk_only / hold）说明单腿到期时 plan 的含义。

回测逐指数结果的 `in_portfolio` 与信号准确率按当日实际持仓统计（`target_weight` 仍记录引擎目标）；信号等级按 regime 覆盖后生效的评分模式判定。因子计算异常生成 `COMPUTE_FAILED` 告警，择时因子全部缺失的交易日生成 `TIMING_DEGRADED` 告警（当日按中性 regime 运行）。

双周调仓的奇偶周以 2016-01-04 所在周为第 1 周连续计数，不使用 ISO 周号（53 周年份会让第 53 周与次年第 1 周同为奇数周）；2020-W53 之前两种计数奇偶一致。

- 研究期固定为 2016-01-01 至 2025-12-31；2026-01-01 起为验证期。
- `purpose=research` 不能越过研究期末端；validation/monitor 可用验证期，但会留下消费记录。
- 默认执行模型 `t_plus_1_open`，可选 `t_plus_1_close`；不同模型不可横向比较。
- 汇总收益是毛收益；详情页在读取时按换手率给出多档成本折算，不重跑历史回测。
- 交易日历不可用时拒绝给出近似结果，而不是退化为工作日历。

稳健性、优化与生命周期的规则见[策略稳健性评估与生命周期监控实施说明](策略稳健性评估与生命周期监控实施说明.md)。

## 扩展约定

1. 新因子以一个模板表示一套计算逻辑；周期、窗口等可调值写入 `parameter_schema`，不得新建带周期后缀的重复模板。
2. 新 transform 注册到 `engine/score.py` 的 `_TRANSFORM_REGISTRY`。
3. 新组合权重方法实现 `WeightAllocator` 并在 `engine/portfolio.py` 注册。
4. 新外部数据集必须走数据管理、健康快照和持久化队列，详见[数据管理与外部数据接入规范](数据管理与外部数据接入规范.md)。
