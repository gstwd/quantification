# A 股指数量化系统策略架构

本文档描述当前运行架构与口径；策略研究方法、参数高原和生命周期原则分别见链接文档，不在此重复定义。

## 边界与资产域

- 系统研究 A 股指数，频率为日频；不提供 ETF、个股交易或交易执行能力。
- 策略资产只能来自 `benchmark_index`，并且应有市场中实际 ETF 对应物。
- 申万行业和个股数据仅能作为 `rrg_industry_match_score`、`index_diffusion_ratio` 等指数级因子的内部输入；它们不能进入策略 `index_codes` 或作为回测标的。

## 执行管线

```text
StrategyEngine.run(config, context)
  → [可选] Timing
  → Score
  → [可选] Filter
  → Rank
  → [可选] Portfolio
  → [可选] Risk
  → EngineResult
```

`RebalanceScheduler` 在回测中决定何时实际重建成分和调整风险仓位；非执行日沿用已有持仓。`portfolio` 缺省为 `equal_weight`。

| 组件 | 当前职责 |
| --- | --- |
| Timing | 根据市场级因子生成 offensive / neutral / defensive regime。综合分在 0-100 空间加权：模板未声明 `native_0_100`（RSI、市场宽度、估值百分位等原值即 0-100）的择时因子必须配置 `transforms`，否则校验报错。代理指数由 `select_timing_proxy_values()`（实时与回测共用）选择：按 `proxy_index_codes` 顺序取第一个让全部择时因子都有值的代理，无代理全覆盖时逐因子回退，择时明细标出 `proxy_index_code` / `proxy_mode` 与各因子来源。择时因子全部缺失时按 `on_degraded` 回退（neutral 默认 / defensive / hold_previous；hold_previous 沿用上一决策日的有效 regime，降级回退不受状态层约束）。综合方式 `combine`：weighted（默认，加权综合分过阈值）或 rules（`rules.defensive` / `rules.offensive` 两个与 FilterConfig 同结构的规则组，比较因子原值，防守优先，都不满足为中性）。`factor_proxies` 可按因子指定代理，代理选择按组进行（`select_grouped_timing_proxy_values()`）。原始 regime 之后经状态层 `timing.state`（滞回 → 无信号维持 → 确认天数 → 最短持有，纯函数在 `domain/strategies/timing_state.py`，编排在 `engine/timing.evaluate_timing()`）得到有效 regime；回测主循环逐日传递状态，实时 `ContextBuilder` 在择时依赖历史时回放最近 250 个交易日重建状态，与回测同一实现。默认参数下状态层为恒等变换；`state.max_exposure_step` 限制档位决定的目标仓位每个决策日的最大变动（如 0.25 即每次最多一档）。可选多档仓位 `timing.tiers`（按顺序首个命中的档位决定目标总仓位）：加权模式按综合分 ≥ `min_score`（严格降序，regime 仍按阈值），规则模式每档一组规则并声明 `regime`（与 `rules.offensive/defensive` 互斥，都未命中为中性）。每档的仓位方式三选一：固定 `exposure`、`hold`（维持上一仓位）或 `exposure_delta`（相对上一仓位增减，限制在 `min_exposure`~`max_exposure`）；含 hold / exposure_delta 档位时必须给出起点 `tier_base_exposure`。有效档位跟随有效 regime——状态层沿用前 regime 时同时沿用上一档位，同 regime 内换档当日生效，档位序号随 `TimingState.tier` 逐日传递 / 回放；未命中或降级时回退 regime 仓位表。条件仓位上限 `timing.exposure_caps`：规则组（比较择时代理上的市场级因子原值）满足时封顶目标总仓位，多条命中取最小值，施加在档位 / regime 仓位之后、组合级风控之前。 |
| Score | absolute 按 `Σ(|w| × d) / Σ|w|` 逐资产评分，`d = transform(value)`，负权重时 `d = 100 − transform(value)`（反向）；rank/zscore 先对每个因子做横截面标准化（rank 平均秩百分位、zscore 标准分），再按权重合成并对综合值做 0-100 映射。缺失策略 `zero` 表示"按最差处理"：absolute 下该因子记 0 分，横截面模式下比有值资产中方向最差者再差一档（rank 一个名次、zscore 一个标准差）。 |
| Filter | 支持 `gt/lt/gte/lte/eq/neq/between`、AND/OR 和跨因子比较。 |
| Rank | 固定按综合得分排序并截取 TopN/BottomN，得分相同按指数代码升序；`momentum_factor` / `valuation_factor` 只产出展示用子排名（估值按原值升序）。`buffer_n`（需 top_n）：调仓前已持有的资产排名仍在 top_n + buffer_n 内时保留，剩余名额按排名补足（读 `EngineContext.current_holdings`）。 |
| Portfolio | equal_weight、score_weight、winner_take_all、inverse_vol（权重 ∝ 1/`vol_factor`，该因子是决策必需因子）或 risk_parity（`EngineContext.return_panel` 近 `cov_window` 日原始收盘收益协方差求等风险贡献，共同有效天数不足一半退回等权）；目标总仓位由 `resolve_target_exposure()` 统一决定，无择时时用 `default_exposure`。有择时但未配置 `timing_exposure` 时用默认三档表 `_DEFAULT_TIMING_EXPOSURE`；`timing_exposure` 只写部分 regime 时缺失档位回退到 `default_exposure`（校验给 warning，应三档写全）。择时命中多档仓位时 `TimingSignal.exposure` 优先于按 regime 查表（含 regime_rules 覆盖的 `timing_exposure`），再经组合级风控上限裁剪。 |
| Risk | 限制单资产权重、总仓位和最低现金比例。引擎另输出 `timing_target_exposure`（regime 仓位经组合级风控裁剪），与当日选股结果无关。路径依赖叠加层 `vol_target` / `drawdown_stop` / `trailing_stop` 不在逐日无状态的引擎里，见下文"路径依赖"。 |

配置中的枚举字段（评分模式、缺失策略、过滤操作符与逻辑、排序方向、权重方法、regime 名称）由 schema 严格约束，写错在解析期即被拒绝；`regime_rules` 覆盖块与顶层执行同一套跨字段校验。

**评分前剔除（实时与回测共用）**：引擎在 regime 覆盖之后、评分之前，按生效配置剔除"决策必需因子"缺失的资产——评分 `missing_factor_strategy=exclude` 的评分因子，以及 AND 逻辑下 `missing_strategy` 为 fail/exclude 的过滤因子；市场级模板引用豁免。ignore / zero / pass 与 OR 逻辑下的缺失由各模块按原语义处理。剔除明细写入 `EngineResult.excluded`，实时返回 `CANDIDATE_EXCLUDED` 提示，回测合并进候选池时间线（原因码 `MISSING_FACTOR`）。回测 `_build_candidate_pool` 只判定行情可执行性（收盘、高低价、次日行情、开盘价）。

## 参数化因子现算

策略因子引用可以直接是模板 ID，也可在 `factor_aliases` 中声明别名、模板和参数：

```json
{
  "score": {"factors": {"short_mom": 0.3, "long_mom": 0.7}},
  "factor_aliases": {
    "short_mom": {"template_id": "return", "params": {"period": 5}},
    "long_mom": {"template_id": "return", "params": {"period": 20}}
  }
}
```

`FactorProvider` 收集引用并由 `FactorTemplateRegistry` 解析为规范化实例。实时分配通过 `load_asset_factor_matrix()` 和 `load_market_factors()` 从原始数据计算当前交易日；回测通过 `precompute_backtest_factors()` 使用预加载数据批量计算。`ContextBuilder` 只读地将这些结果组装为 `EngineContext`。

派生因子 `expr` 支持时序函数 `delay / delta / ts_mean / ts_std / ts_zscore / ts_rank(x, n)`：`compute_matrix` 把求值轴向前扩展 `series_window` 个交易日并补齐目标日之间的全部交易日，按 交易日 × 指数 数组求值后只保留目标日；不含时序函数的表达式逐日标量求值。派生实例回望 = 依赖回望 + 窗口折算，超过回测行情预加载在校验期拒绝。截面函数不提供，截面标准化由评分 `scoring_mode` 按日候选池完成。

因子值不持久化，也没有因子值补算任务。`factor_definition` 保存的是模板目录；原始数据不足或计算失败会作为结构化缺失结果返回。模板与参数约定见[因子研发与集成指引](因子研发与集成指引.md)。

## 回测与可比性

`BacktestService` 在创建时快照策略配置和哈希，执行时优先使用快照；快照存在但解析失败时回测直接失败，不回退到当前配置（无快照的存量回测读取当前配置）。每个结果记录候选池、调仓日历来源、换手模型、记账口径、数据质量口径、基准和执行模型。

**记账口径 `drift_v1`**（`domain/portfolio/execution.py`，回测 params 写 `_accounting_model`）：第 k 行收益窗口为 [收盘 T_k, 收盘 T_{k+1}]，最后一个交易日不落行；持仓在调仓之间随行情漂移（`w' = w(1+r)/(1+R)`），换手按漂移后的实际持仓计算；T+1 开盘调仓日旧仓位承担隔夜段、新仓位承担日内段，两段复利；收益结算用前向填充行情（缺口期间平盘、缺口后补回涨跌），候选池、因子与缺口统计仍看原始行情。缺 `_accounting_model` 的存量回测按 `constant_mix_v0`（每日再平衡）标注，两种口径不可直接比较。

**持仓日与胜率**：执行后持仓里至少有一个正权重才算持仓日（`domain/portfolio/accounting.has_positive_weight`）；`active_days`、胜率（只统计持仓日）与数据缺口资产计数都按这一判定，择时降到零仓位时的零权重持仓不计入。

**基准与归因**：基准按决策日归因（第 k 行为 [收盘 T_k, 收盘 T_{k+1}] 的基准收益），可用单一指数或 `benchmark_mix`（多指数 + 现金的恒定比例，等价于每日再平衡）；收益归因见 `domain/portfolio/attribution.py`。

**独立对账**：`domain/portfolio/reconcile.py` 按上述规格从落库逐日结果与原始行情独立复算逐日收益、换手、持仓连续性、累计收益、回撤、基准与汇总指标，不导入 `quant_etf_api` 下任何模块（测试守卫），因此执行器的实现缺陷会表现为差异；`backtest verify <id>`（`services/backtest_reconcile_service.py`）对落库回测做只读对账，有差异时退出码为 1。差异也可能来自回测之后行情被上游修订：用同一快照重跑后再对账即可区分。冻结口径另由金样本 `tests/unit/test_caliber_golden.py` 守卫。

T+1 收盘执行中，昨日指令先在今日收盘成交，今日新指令的双腿合成以该成交后的持仓为基准。仅风险腿到期时只缩放已成交成分，不恢复成交前成分；明确清仓的空字典与没有待执行指令的 `None` 必须区分。仅选择腿到期时也维持今日成交后的总仓位。

双腿单独到期的合成（`compose_two_leg_positions`）：仅风险腿到期时按 `timing_target_exposure` 缩放现有成分——当日过滤后无入选资产或入选资产被单资产上限裁剪，都不会让风险腿清仓或压低仓位；仅选股腿或仅风险腿到期时，缩放后的持仓都按单资产上限裁剪，超出部分留作现金。两腿同日到期时直接采用引擎目标。实时星标摘要用 `plan_mode`（full / selection_only / risk_only / hold）说明单腿到期时 plan 的含义。

回测逐指数结果的 `in_portfolio` 与信号准确率按当日实际持仓统计（`target_weight` 仍记录引擎目标）；信号等级按 regime 覆盖后生效的评分模式判定。因子计算异常生成 `COMPUTE_FAILED` 告警，择时因子全部缺失的交易日生成 `TIMING_DEGRADED` 告警（当日按 `on_degraded` 回退，默认中性），部分缺失的交易日生成 `TIMING_PARTIAL_MISSING` 告警（综合分只由剩余因子重新归一化权重得出）。

择时只做度量、不改决策：配置择时的回测在执行时由 `domain.research.timing` 汇总 `metrics.timing_stats`（regime 占比与翻转、风险腿到期日的 regime / 目标仓位切换、分 regime 收益、换手按调仓腿拆分、综合分分位；配置 `timing.tiers` 时另有按有效档位分组的 `tiers`），缺少该块的存量回测不补算。择时净贡献用 `research batch --timing-attribution` 的关闭择时对照回答。因子中心研究台的「择时综合分」与回测同一实现：按回测口径现算择时因子，逐日经 `ContextBuilder` 调用 `DefaultScoreCalculator.calculate_timing`，可选任一策略的 timing 块。

**路径依赖（排名缓冲、偏离调仓、风控叠加层）**：回测主循环在 `compose_two_leg_positions` 之后调用 `domain/strategies/risk_overlay.resolve_day_target()`：非调仓日持仓相对最近一次成交目标的最大偏离超过 `rebalance.band.max_drift` 时回到该目标；随后叠加层依次移出移动止损冷却中的资产、在回撤止损期间把总仓位压到 `drawdown_stop.exposure`、按 `vol_target` 事前波动率等比降仓（三者只减仓，清出的权重留作现金）；最后调仓日所需单边换手低于 `band.min_turnover` 时跳过（止损强制成交不跳过）。结算 [T, T+1] 后用组合收益与持仓资产原始收盘价推进 `RiskOverlayState`，新触发的止损在下一决策日强制成交。未启用这些功能时 `resolve_day_target()` 原样返回两腿合成目标，成交只由调仓日历决定；启用时回测 params 写 `_risk_overlay_model=overlay_v1`。排名缓冲 `rank.buffer_n` 由引擎 Rank 读取主循环注入的 `EngineContext.current_holdings`，同样依赖主循环维护的持仓路径。实时决策（`StrategyConfig.needs_path_state`）用 `persist=False` 的同一主循环从回放起点（LIVE 取上线日且至少 60 天，其余约一年）回放到有效交易日，再用 `BacktestService.decide_with_path_state()` 合成今日目标，`plan.path_state` 给出回放起点、今日是否成交与原因。

**组合策略（`kind=composite`）**：`config_json` 为 `CompositeStrategyConfig`（成员 + 权重 + 现金 + 成员权重再平衡日程），引擎配置解析为 None，由 `get_composite_config` 读取。回测创建时快照内嵌各成员配置与哈希；执行时逐成员走 `persist=False` 主循环，再由 `domain/portfolio/composite.blend_members()` 逐日合成：组合收益 Σ W_m r_m，成员权重随净值漂移、在再平衡日调回目标，换手按合成持仓（成交前 / 成交后）计算从而在成员间轧差，params 写 `_composite_model=position_blend_v1`。实时分配逐成员决策后加权合成。稳健性、优化、研究批量、信号诊断与战役模式拒绝组合策略。

双周调仓的奇偶周以 2016-01-04 所在周为第 1 周连续计数，不使用 ISO 周号（53 周年份会让第 53 周与次年第 1 周同为奇数周）。

- 研究期固定为 2016-01-01 至 2025-12-31；2026-01-01 起为验证期。
- `purpose=research` 不能越过研究期末端；validation/monitor 可用验证期，但会留下消费记录。
- 系统级默认执行模型 `t_plus_1_open`，可选 `t_plus_1_close`；研究与优化 CLI 缺省 `t_plus_1_close`（`RESEARCH_DEFAULT_EXECUTION_MODEL`）；不同模型不可横向比较。
- 汇总收益是毛收益；详情页在读取时按换手率给出多档成本折算，不重跑历史回测。
- 交易日历不可用时拒绝给出近似结果，而不是退化为工作日历。

稳健性、优化与生命周期的规则见[策略稳健性评估与生命周期监控实施说明](策略稳健性评估与生命周期监控实施说明.md)。

## 扩展约定

1. 新因子以一个模板表示一套计算逻辑；周期、窗口等可调值写入 `parameter_schema`，不得新建带周期后缀的重复模板。
2. 新 transform 在 `engine/transforms.py` 用 `register_transform()` 注册（另有参数化的 `linear(lo,hi)`）。
3. 新组合权重方法实现 `WeightAllocator` 并在 `engine/portfolio.py` 注册。
4. 新外部数据集必须走数据管理、健康快照和持久化队列，详见[数据管理与外部数据接入规范](数据管理与外部数据接入规范.md)。
