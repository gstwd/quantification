# 因子研发与集成指引

> 适用范围：本系统全部因子（指数因子、行业 / 成分类指数级因子、派生因子与后续新增因子）。
> 本文件说明因子模板的结构约定，以及“先研究、再登记、后配置”的流程。
>
> 资产边界：策略可配置资产只能是 `benchmark_index` 中用户自行添加、且市场上存在实际 ETF
> 对应物的 A 股指数；行业与个股只作为因子输入，不作为策略资产（申万 801xxx 不进入策略 /
> 回测标的范围）。

## 一、两级体系：因子中心与研究页

- **因子中心（正式因子）**：`factor_definition` 中 `is_active=true` 的**因子模板**，可被策略配置
  引用、参与实时分配与标准回测。目录由代码注册表同步：`init-factors`（或 `POST /api/factors/init`）
  把 `factors/catalog.py` 中的模板写入 `factor_definition`，并把代码中已不存在的模板行置为
  `is_active=false`。模板清单与元数据以 `GET /api/factors/` 或因子中心页面为准。
- **研究页（独立实验）**：因子中心菜单下的研究页面（“RRG / 扩散研究”“量价 / 择时研究”）。
  用于按单篇研报或单条因子假设做独立实验：与正式系统只共享**只读数据**（行业日线、成分、
  个股收盘、指数行情等），不创建策略、不持久化回测，可携带自定义参数即时计算观察。
- **晋升门槛**：研究页结论达到以下条件后方可登记为正式因子：
  1. 口径定稿（复权 / PIT / 成分回写 / 缺数处理等有明确说明）；
  2. 参数空间确定（可调参数给出类型、取值范围与默认值，并声明参数化回望窗口）；
  3. 计算方案可行（实时按请求现算、回测区间内批量预计算，不逐日重复扫全量 bar）；
  4. 回测口径通过验证（标准回测中心收益正确、有基准对照）；
  5. 可观测性达标（数据状态 / 缺口 / 预热期对前端可见）。

## 二、因子模板

一个模板描述“如何计算一类因子”，而不是某个固定参数的因子：一条 `factor_definition` 对应一个
模板，`factor_id` 即模板 ID；同一计算逻辑的不同参数取值不单独登记，模板 ID 不携带具体参数取值。

模板（`factors/templates.py` 的 `FactorTemplate`）的主要字段：

| 字段 | 取值 | 作用 |
| --- | --- | --- |
| `template_id` / `name` / `version` / `description` | — | 标识、展示名、版本与说明；版本参与计算身份 |
| `category` | breadth / constituent / derived / macro / market / momentum / price / relative_strength / technical / valuation / volatility / volume | 语义族，用于展示与分组 |
| `value_shape` | asset / market | 每资产值或市场级值，决定计算与装载方式 |
| `usage` | timing / score / filter / rank 的子集 | 能被策略管线哪些模块消费；配置校验与前端下拉按此过滤 |
| `parameter_schema` | 参数名 → `ParameterSpec`（`type`: integer / number / choice / text，`minimum`、`maximum`、`default`、`description`、`choices`） | 可覆盖参数；空表示零参数模板。`choice` 用于同一算法作用于不同输入字段（如 `valuation_percentile.field`） |
| `default_params` | 键值对 | 未在 `parameter_schema` 中声明的固定口径（如 `index_diffusion_ratio` 的 `weighting_mode`） |
| `required_data` | 原始数据集元组 | 计算所需的原始数据（行业面板等只作内部依赖，不作为可配置因子） |
| `base_lookback_days` / `compute_lookback_days` | 天数 / 按参数推导 | 回望窗口；上下文按策略实际参数取最大回望加载数据 |
| `market_scope` | bool | 是否需要全市场活跃指数行情（如 `breadth_ma_pct`） |
| `native_0_100` | bool（代码侧语义） | 原值是否天然处于 0-100 评分空间（RSI、市场宽度、估值百分位等）；择时综合分里未声明该语义的因子必须配置 `transforms` |

usage 按语义声明：多数资产级模板为 timing / score / filter / rank；价格位置类（`sma`、`close_price`、
`atr`、`donchian_high`、`donchian_low`、`monthly_ma`、`pv_resonance`）只用于 timing / filter；
量价与行业 / 成分匹配类（`amount_volatility`、`price_volume_corr`、`index_diffusion_ratio`、
`rrg_industry_match_score`）用于 score / filter / rank；市场级模板（`breadth_ma_pct`、`macro_series`、
`market_series`）只用于 timing / filter，不得放入 score / rank。

**回望上限**：回测的行情加载窗口是常量（注册表默认参数下 lookback 的最大值，730 天），因此任一合法
参数组合推导出的回望都不能超过它，否则长窗口因子会在回测前段静默算成 `None`
（`test_no_legal_params_exceed_backtest_warmup` 守护）。只依赖估值的长窗口模板
（`STRATEGY_SCOPED_VALUATION_TEMPLATE_IDS`，即 `valuation_percentile`）例外：回测按策略实例回望单独
扩展估值预加载。派生因子超过回测预加载的回望在配置校验期拒绝。

## 三、策略引用、计算身份与现算路径

- 策略用 `factor_aliases` 声明“别名 → 模板 + 参数”：

  ```json
  {
    "factor_aliases": {"trend_fast": {"template_id": "sma", "params": {"period": 10}}},
    "timing": {"factors": {"trend_fast": 1.0}, "transforms": {"trend_fast": "trend_score"}}
  }
  ```

  未在别名中声明的引用名本身就是模板 ID（用默认参数）。权重与变换写在各模块（`score` /
  `timing` 等）里，别名只承载“用哪个模板、什么参数”。
- 参数的补齐、类型 / 范围校验与规范化由 `FactorTemplate.resolve_params()` 完成：以默认值补齐、
  拒绝未知字段、校验类型与范围，再序列化为稳定 JSON。**模板 ID + 模板版本 + 规范化参数**构成一次
  计算实例的身份，用于请求内复用与口径指纹；同参的多个别名只算一次。
- 统一现算：实时分配、因子详情、回测、稳健性与研究扫描都按当次配置从原始数据批量计算，先按实际
  参数推导最大回望并一次性预加载所需数据，在当次请求或任务内复用中间结果，结束即释放。因子值
  不落库，没有值表、补算队列或缓存失效链路；缺失只有三种原因：模板未知、原始数据不足、计算失败，
  均以结构化结果返回。实时路径只读，不写库、不入队。

## 四、派生因子（`expr`）

- 在 `factor_aliases` 中用 `template_id: "expr"` 声明，`params.expr` 为表达式文本，引用其他别名或
  模板 ID。安全白名单见 `factors/expression.py`：四则运算与乘方、一元正负号，函数 `abs` / `min` /
  `max` / `log` / `sqrt` / `sign`，时序函数 `delay(x, n)` / `delta(x, n)`（n ≥ 1）与 `ts_mean` /
  `ts_std` / `ts_zscore` / `ts_rank(x, n)`（n ≥ 2，窗口含当日），窗口上限 250；表达式不超过 200 字符、
  60 个语法节点。
  不提供截面函数，截面标准化由评分 `scoring_mode` 按日候选池完成。
- 依赖在注册表解析时绑定，`FactorComputeService.compute_matrix` 先算依赖再求值；含时序函数时向前
  扩展求值轴，实例回望 = 依赖回望 + 窗口折算。
- 派生因子进入 `research batch` 变体或 `optimization start` 候选前，必须先有 `research factor-ic`
  或 `research buckets` 的诊断记录（台账 `kind=diagnostic`，按与别名无关的指纹匹配）。

## 五、开发流程（新增或改造因子）

1. 在研究页先做数据研究：口径、覆盖、预热期、与同类因子的相关性 / IC 评估；
2. 实现计算器并注册模板：计算器实现 `FactorComputer`（回测常用者再实现 `BatchFactorComputer`），
   在 `factors/catalog.py` 登记模板并声明 `parameter_schema`、`compute_lookback_days`、
   `instance_label` 与元数据，然后运行 `init-factors`；
3. 接入现算路径：实时分配与因子详情按请求现算，回测在任务开始时预加载区间数据并批量现算；
4. 月度宏观新指标须登记 `factors/macro_period._MONTHLY_RELEASE_DAY` 发布滞后与
   `domain/market_data/indicators.MACRO_INDICATOR_CODES`，否则实时路径不加载或产生前视；日频
   市场指标入 `market_indicator`，交易日当日可见；
5. 开放策略引用：配置校验按 usage 限制消费位置，前端表单同步该模块的因子下拉；新增参数无需改前端
   （参数表单由 `parameter_schema` 驱动）；
6. 标准回测验收：走回测中心，校验 T+1 口径、基准对照、缺口 / 预热告警。

## 六、行业与成分类因子

行业数据是研究数据层与指数级因子的输入：

- 行业面板算法（RS-Ratio / RS-Momentum / 象限 / 行业扩散）由 `domain/industry` 纯函数与
  `IndustryFactorService` 维护，研究工作台 `/industry/*` 按自定义参数即时计算，不创建策略、
  不写因子值。行业本身不是可配置因子，策略层没有 rotation 模块或行业资产域。
- 指数级行业 / 成分因子：`rrg_industry_match_score`（先按研报信号对全部活跃申万一级行业做选择，
  再按指数成分股的申万行业暴露与选中行业集合计算重合匹配分）、`index_diffusion_ratio`（指数成分股
  上涨占比）、`constituent_valuation` / `constituent_turnover` / `constituent_mainflow`（成分股估值、
  换手与主力资金的聚合，带最低覆盖率参数），均为 `value_shape=asset`。
- 指数成分按 Tushare `index_weight` 优先、AkShare csindex / Baostock 兜底获取；历史 PIT 成分覆盖
  不足的指数，成分类因子从成分可用日起才有值。

## 七、其他约定

- 同一计算逻辑只保留一个模板：新增同族周期 / 窗口时扩展 `parameter_schema`，不新增带周期后缀的模板 ID。
- 配置校验失败应在策略创建 / 编辑时即返回明确中文原因（含 usage），不允许“后端已支持某配置但前端
  无选项”或“前端可选但后端拒绝”的不一致。
