# 市场记忆与研究日志模块 — 技术设计文档（V2）

## 一、概述

### 1.1 模块定位

本模块是一个**完全独立**的研究日志系统，核心功能：

- 以交易日为单位，记录每日市场观察、主观评分、非结构化分析
- 系统自动填充已有的指数行情数据和因子值，作为日志的"事实快照"
- 用户手动补充系统无法自动获取的数据（广度、资金流向、风格判断等）
- 支持 AI 辅助分析（LLM 集成）
- 支持标签分类和历史回顾检索

**独立性约束**：本模块不与现有策略引擎、因子计算、回测等模块联动。仅**读取**现有数据表（`index_daily_bar`、`index_factor_value`、`benchmark_index`、`trading_calendar`）用于自动填充快照，不写入任何现有表，不触发任何策略/回测逻辑。

### 1.2 核心设计原则

| 原则 | 说明 |
|---|---|
| **事实与观点分离** | 自动快照 + 手动结构化数据 = Facts；观察分区 = Insights。独立存储，独立展示 |
| **快照不可变** | 日志创建后，自动填充的快照数据不随系统数据更新而改变（反映记录时刻的市场状态） |
| **手动输入为主、自动填充为辅** | 自动填充减少重复劳动，手动输入是研究过程的核心 |
| **独立部署** | 新增表、API、前端页面完全独立，不修改现有代码 |

### 1.3 与原始设计方案（V1）的差异

| 调整项 | V1 方案 | V2 方案 |
|---|---|---|
| 系统已有数据 | 要求手动录入 | 自动填充并快照保存 |
| 因子沉淀功能 | 包含 | 暂不实现，仅做日志记录 |
| 与其他模块联动 | 假设验证→回测 | 暂不联动，完全独立 |
| 资讯聚合 | 包含 | 纳入后续迭代 |
| 手动录入字段 | 概念列表 | 逐字段评估必要性，完整定义 |

### 2.2 建表 DDL

#### 2.2.1 journal_entry — 每日日志主表

```sql
CREATE TABLE journal_entry (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    trade_date      DATE NOT NULL UNIQUE,

    -- 核心主观评分（0–100，步长 1，NULL 表示未填写）
    market_temperature   SMALLINT CHECK (market_temperature   BETWEEN 0 AND 100),
    profit_effect        SMALLINT CHECK (profit_effect        BETWEEN 0 AND 100),
    risk_preference      SMALLINT CHECK (risk_preference      BETWEEN 0 AND 100),
    trading_difficulty   SMALLINT CHECK (trading_difficulty   BETWEEN 0 AND 100),
    market_consistency   SMALLINT CHECK (market_consistency   BETWEEN 0 AND 100),

    -- 市场阶段（见 §8.2 枚举定义）
    market_phase      VARCHAR(32),

    -- 一句话摘要
    one_line_summary  VARCHAR(256),

    -- 状态标记
    is_complete       BOOLEAN DEFAULT FALSE,
    word_count        INTEGER DEFAULT 0,

    created_at        TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at        TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_journal_entry_trade_date ON journal_entry (trade_date);
CREATE INDEX idx_journal_entry_phase      ON journal_entry (market_phase);
CREATE INDEX idx_journal_entry_complete   ON journal_entry (is_complete);
```

**字段设计说明**：

- **market_temperature（市场温度）**：对市场整体状态的综合判断，0=冰点，50=中性，100=过热。这是回顾历史时最重要的排序/筛选维度之一。
- **profit_effect（赚钱效应）**：当日买入获利的难易程度，0=极难赚钱，100=闭眼赚钱。有别于市场温度——震荡市可能温度不高但赚钱效应尚可（结构性行情）。
- **risk_preference（风险偏好）**：市场参与者的风险偏好水平，0=极度规避风险，100=极度追逐风险。高偏好→题材/小盘活跃，低偏好→红利/大盘防御。
- **trading_difficulty（交易难度）**：实际操作难度，0=极难操作（追高就套），100=极易操作（买什么都涨）。这是实战维度，与赚钱效应互补——有时候指数涨但轮动极快，赚钱效应中等但交易难度很高。
- **market_consistency（市场一致性）**：指数间走势一致程度，0=极端分化，100=全面同涨同跌。一致性低时结构选择比仓位选择更重要。
- **market_phase（市场阶段）**：枚举值（trending_up / trending_down / ranging / rotation / euphoria / panic / repair），用于快速标记市场所处的宏观阶段。

每个字段各自独立、不可互相推导，组合使用可形成多维度的市场画像，便于后续查询"高温+高难度"或"低一致+高偏好"等特定组合场景。

#### 2.2.2 journal_index_snapshot — 自动填充指数快照

```sql
CREATE TABLE journal_index_snapshot (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    entry_id        UUID NOT NULL REFERENCES journal_entry(id) ON DELETE CASCADE,

    index_code      VARCHAR(32) NOT NULL,
    index_name      VARCHAR(128) NOT NULL,
    index_category  VARCHAR(32),             -- broad / industry / theme
    sort_order      SMALLINT DEFAULT 0,

    -- 行情数据（来源：index_daily_bar）
    close_price     DECIMAL(12,4),
    change_pct      DECIMAL(8,4),            -- 日涨跌幅（%）
    volume_ratio_20d DECIMAL(8,4),           -- 20 日量比

    -- 动量数据（来源：index_factor_value）
    return_5d       DECIMAL(8,4),
    return_20d      DECIMAL(8,4),
    return_60d      DECIMAL(8,4),
    return_120d     DECIMAL(8,4),

    -- 技术指标（来源：index_factor_value）
    ma_20d_deviation   DECIMAL(8,4),         -- 收盘价偏离 MA20（%）
    ma_60d_deviation   DECIMAL(8,4),
    ma_120d_deviation  DECIMAL(8,4),
    volatility_20d     DECIMAL(8,4),         -- 20 日波动率（%）
    max_drawdown_60d   DECIMAL(8,4),         -- 60 日最大回撤（%）

    UNIQUE (entry_id, index_code)
);

CREATE INDEX idx_journal_snapshot_entry ON journal_index_snapshot (entry_id);
```

**设计说明**：快照表仅保存**当日可获取的最新行情与技术指标值**。每个指数一行，查询"某日志中所有指数表现"时一次 JOIN 即可。

#### 2.2.3 journal_market_data — 手动结构化市场数据

```sql
CREATE TABLE journal_market_data (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    entry_id        UUID NOT NULL UNIQUE REFERENCES journal_entry(id) ON DELETE CASCADE,

    -- ========== 全市场广度（来源：同花顺/Wind/东财终端，手动录入） ==========
    -- 广度数据反映市场参与面的健康程度，是指数之外最重要的市场维度
    market_up_stocks       INTEGER,           -- 全市场上涨家数
    market_down_stocks     INTEGER,           -- 全市场下跌家数
    market_flat_stocks     INTEGER,           -- 全市场平盘家数
    limit_up_stocks        INTEGER,           -- 涨停家数（不含一字板）
    limit_down_stocks      INTEGER,           -- 跌停家数（不含一字板）

    -- ========== 成交与资金（来源：同花顺/Wind，手动录入） ==========
    -- 资金面数据是重要的领先指标，当前自动采集未覆盖
    total_turnover_yi       DECIMAL(10,2),    -- 全市场成交额（亿元）
    turnover_vs_prev_pct    DECIMAL(6,2),     -- 成交额较前日变化（%）
    north_bound_net_yi      DECIMAL(8,2),     -- 北向资金净流入（亿元）
    margin_balance_change_yi DECIMAL(8,2),    -- 两融余额较前日变化（亿元）

    -- ========== 风格判断（枚举值，手动选择） ==========
    -- 风格是 ETF 轮动的核心驱动因子，自动系统难以量化
    size_style          VARCHAR(16),          -- large_cap / small_cap / balanced
    growth_style        VARCHAR(16),          -- growth / value / balanced
    sector_leading      VARCHAR(32),          -- tech / dividend / cyclical / financial / consumption / healthcare / balanced

    -- ========== 行业表现（手动录入，文本型） ==========
    top_sectors         TEXT,                 -- 领涨行业前 5，逗号分隔，如 "半导体,通信,计算机,传媒,电子"
    bottom_sectors      TEXT,                 -- 领跌行业前 5，逗号分隔

    -- ========== 元数据 ==========
    data_source         VARCHAR(128),         -- 数据来源说明，如 "同花顺 + Wind"
    notes               TEXT                  -- 补充备注
);
```

**手动字段必要性逐项论证**：

| 字段组 | 必要性论证 |
|---|---|
| **上涨/下跌/平盘家数** | 指数涨跌只反映加权平均，上涨家数反映市场参与面。典型案例：权重股拉涨但 3000+ 个股下跌——只看指数会误判市场。每日记录积累后可做"涨跌比"时间序列分析，识别背离信号 |
| **涨跌停家数** | A 股特色的情绪指标。涨停家数 > 100 vs < 30 反映的市场情绪完全不同。结合指数走势可识别"指数温和但情绪火爆"的题材市 vs "指数不跌但情绪冰点"的防御市 |
| **全市场成交额** | 量在价先。缩量上涨 vs 放量下跌含义完全不同。单日值意义有限，但连续记录形成的时序趋势是仓位管理的重要参考 |
| **北向资金** | A 股市场公认的"聪明钱"风向标，大幅流入/流出常领先市场拐点。手动记录每日值比事后查更方便回顾 |
| **两融余额变化** | 杠杆资金的边际变化反映风险偏好，连续增加通常对应风险偏好提升期 |
| **大小盘风格** | ETF 轮动的核心决策变量。当前系统只能通过指数对比间接推断，直接的主观判断结合了盘面感受，是回顾时最有价值的字段之一 |
| **成长/价值风格** | 同理，是行业 ETF 轮动的核心因素。主观判断整合了板块表现、资金流向、估值等多维信息 |
| **领涨/领跌行业** | 记录当日盘面的直观感受。积累后可分析行业轮动规律（如"消费连续领涨 3 天后会发生什么"） |

## 三、手动录入字段详细说明与录入指南

本节为 `journal_market_data` 和 `journal_entry` 中所有手动字段提供完整的录入指南，包括：数据来源（在哪看）、录入方式（怎么填）、量化标准（如何判断）、前端校验规则。

### 3.1 全市场广度（来源：同花顺/东方财富/Wind 终端）

**数据查看路径**（以同花顺 PC 版为例）：
- 打开同花顺 → 行情中心 → 市场概况（快捷键 61/63 分别查看沪市/深市）
- 或：沪深行情 → "上涨家数/下跌家数/平盘家数"首页即可看到
- 东方财富网页版：`quote.eastmoney.com/center/gridlist.html` → "市场概况"栏目

| 字段 | 说明 | 录入方式 | 前端校验 |
|---|---|---|---|
| `market_up_stocks` | 全市场上涨个股家数 | 手动输入整数 | `SMALLINT`，≥0，≤10000 |
| `market_down_stocks` | 全市场下跌个股家数 | 手动输入整数 | `SMALLINT`，≥0，≤10000 |
| `market_flat_stocks` | 全市场平盘个股家数（涨跌幅=0） | 手动输入整数 | `SMALLINT`，≥0，≤10000 |
| `limit_up_stocks` | 涨停家数（不含 ST、不含一字板封死未打开的） | 手动输入整数 | `SMALLINT`，≥0，≤500 |
| `limit_down_stocks` | 跌停家数（不含 ST、不含一字板封死未打开的） | 手动输入整数 | `SMALLINT`，≥0，≤500 |

> **录入提示**：涨跌停家数在同花顺行情首页可直接看到，通常在"涨停""跌停"标签下。如果使用了专业版 Wind，在 WIT 终端输入 `MKT` 命令查看市场总览。

### 3.2 成交与资金（来源：同花顺/东方财富/Wind 终端）

**数据查看路径**：
- 全市场成交额：同花顺 → 行情中心 → 首页顶部"两市成交额"，或东方财富首页顶部
- 北向资金：同花顺 → 数据中心 → 沪深港通 → 北向资金（或 Wind `SHCG` 命令）
- 两融余额：同花顺 → 数据中心 → 融资融券 → 两融余额（注意是每日收盘后更新，当日看的是**前一日**数据）

| 字段 | 说明 | 录入方式 | 前端校验 |
|---|---|---|---|
| `total_turnover_yi` | 全市场成交额（沪深两市合计），单位**亿元**。例如 8500 亿填 `8500` | 手动输入数字 | `DECIMAL(10,2)`，≥0，建议 1000–50000 |
| `turnover_vs_prev_pct` | 成交额较前一交易日变化的百分比。例如较昨日缩量 5% 填 `-5` | 手动输入数字 | `DECIMAL(6,2)`，-100~200 |
| `north_bound_net_yi` | 北向资金当日净流入（沪股通+深股通合计），单位**亿元**。正值=流入，负值=流出 | 手动输入数字 | `DECIMAL(8,2)`，-300~300 |
| `margin_balance_change_yi` | 两融余额较前一交易日的变化量，单位**亿元**。注意此为**前一交易日**数据（T日只能看到T-1日两融） | 手动输入数字 | `DECIMAL(8,2)`，-500~500 |

> **录入提示**：
> - 成交额是最重要的实时数据之一，同花顺首页顶部醒目位置显示。建议每次录入时**看一眼较前日的变化幅度**并填入 `turnover_vs_prev_pct`。
> - 北向资金在交易时段实时更新，收盘后可查看最终确认值。同花顺 → "北向资金" 可直接看到当日累计净流入。
> - 两融余额**当日不可得**，填前一日数据或留空均可。该字段可选填。

### 3.3 风格判断（来源：综合判断）

风格字段**不需要输入具体数值**，从前端下拉框中选择一个枚举值即可。以下为判断标准：

#### 大小盘风格 `size_style`

| 枚举值 | 中文 | 判断依据（参考） |
|---|---|---|
| `large_cap` | 大盘主导 | 沪深300/上证50 涨幅 > 中证1000/中证2000 涨幅**超过 0.5%** |
| `small_cap` | 小盘主导 | 中证1000/中证2000 涨幅 > 沪深300/上证50 涨幅**超过 0.5%** |
| `balanced` | 均衡 | 大小盘指数涨幅差距在 0.5% 以内 |

**参考数据**：同花顺 → 指数对比 → 添加"上证50""沪深300""中证500""中证1000""中证2000""创业板指"，直接对比涨跌幅。

#### 成长价值风格 `growth_style`

| 枚举值 | 中文 | 判断依据（参考） |
|---|---|---|
| `growth` | 成长主导 | 创业板/科创板/半导体/新能源等成长方向 > 银行/煤炭/公用事业等价值方向**超过 1%** |
| `value` | 价值主导 | 银行/煤炭/公用事业/红利等价值方向 > 成长方向**超过 0.5%** |
| `balanced` | 均衡 | 两大方向涨幅差距不大，无明显偏向 |

**参考数据**：同花顺 → 板块监测 → 对比"半导体""计算机""医药"（成长代表）与"银行""煤炭""电力"（价值代表）的日内走势。

#### 行业主导 `sector_leading`

| 枚举值 | 中文 | 判断依据 |
|---|---|---|
| `tech` | 科技主导 | 半导体/通信/计算机/电子/传媒 中有 ≥2 个行业涨幅排名前 5 |
| `dividend` | 红利主导 | 银行/煤炭/电力/公用事业/交运 中有 ≥2 个行业涨幅排名前 5 |
| `cyclical` | 周期主导 | 有色/化工/钢铁/建材/地产 中有 ≥2 个行业涨幅排名前 5 |
| `financial` | 金融主导 | 券商/保险/银行 整体领涨，且券商涨幅突出 |
| `consumption` | 消费主导 | 食品饮料/家电/汽车/医美/社服 中有 ≥2 个行业涨幅排名前 5 |
| `healthcare` | 医药主导 | 医药/医疗/创新药 中有 ≥2 个子行业涨幅排名前 5 |
| `balanced` | 无明显主导 | 以上各类别中没有明显突出的，轮动快速或全面普涨/普跌 |

> **录入提示**：行业主导的判断不是精确科学，重要的是**记录当日最突出的印象**。如果看不清楚，选择 `balanced` 即可。

### 3.4 行业表现（来源：同花顺/东财板块排行）

**数据查看路径**：
- 同花顺 → 板块 → 行业板块 → 按涨幅排序（查看 Top 5 和 Bottom 5）
- 东方财富 → 行情中心 → 板块排行 → 行业板块

| 字段 | 说明 | 录入方式 | 前端校验 |
|---|---|---|---|
| `top_sectors` | 领涨行业前 5，用**中文逗号**分隔。如 "半导体,通信设备,计算机应用,传媒,电子制造" | 手动输入文本 | `TEXT`，长度 ≤ 256 |
| `bottom_sectors` | 领跌行业前 5，用**中文逗号**分隔。如 "银行,煤炭开采,房地产开发,钢铁,建筑材料" | 手动输入文本 | `TEXT`，长度 ≤ 256 |

> **注意**：使用东方财富/同花顺的行业分类均可以，保持每次从同一来源查看即可，保证前后可比性。

### 3.5 主观评分量化标准（0–100）

本节为 5 个主观评分提供**分层量化参考**，目的是减少"凭感觉乱填"的随机性，让不同日期的评分具有可比性。

#### 市场温度 `market_temperature`（0=冰点，50=中性，100=过热）

参考维度：全市场成交额 + 涨跌比 + 涨停家数 + 指数涨幅。

| 区间 | 标签 | 参考量化标准 |
|---|---|---|
| 0–20 | 冰点 | 成交额 < 5000 亿，下跌家数 > 80%，涨停 < 20 家。市场无人关注 |
| 21–40 | 偏冷 | 成交额 5000–7000 亿，下跌家数 > 60%，涨停 < 40 家。观望氛围浓厚 |
| 41–60 | 中性 | 成交额 7000–10000 亿，涨跌比接近 1:1，涨停 40–80 家。正常交易状态 |
| 61–80 | 偏热 | 成交额 10000–15000 亿，上涨家数 > 60%，涨停 80–150 家。赚钱效应明显 |
| 81–100 | 过热 | 成交额 > 15000 亿，上涨家数 > 80%，涨停 > 150 家。极度亢奋 |

**专业参考**：同花顺 APP 首页"市场温度计"功能，以及韭圈儿/且慢等平台的"市场温度"指标可作为交叉参考，但建议以自己的综合判断为准。

#### 赚钱效应 `profit_effect`（0=极难赚钱，100=闭眼赚钱）

参考维度：上涨家数占比 + 涨停家数 + 盘中追高胜率（主观感受）+ 是否出现"赚指数不赚钱"。

| 区间 | 标签 | 参考量化标准 |
|---|---|---|
| 0–20 | 极难赚钱 | 9 成以上个股下跌，追高即套，无任何可操作机会 |
| 21–40 | 偏难 | 多数个股下跌，仅极少数方向有赚钱机会，容错率极低 |
| 41–60 | 中性 | 结构性行情，选对方向能赚钱，选错方向亏钱，考验方向判断 |
| 61–80 | 偏易 | 多数方向上涨，买主流方向大概率赚钱，容错率较高 |
| 81–100 | 闭眼赚钱 | 全面普涨，几乎买什么都涨，涨停潮，错失焦虑严重 |

> **关键区分**：市场温度高 ≠ 赚钱效应好。典型案例——权重拉指数但 3000+ 个股下跌：温度 60，赚钱效应可能只有 30。此字段**建议每次都填**，是回顾时最实用的筛选维度。

#### 风险偏好 `risk_preference`（0=极度规避风险，100=极度追逐风险）

参考维度：题材股 vs 红利股表现 + 高 beta 板块表现 + 涨停板封单意愿 + 新股/次新股表现。

| 区间 | 标签 | 参考量化标准 |
|---|---|---|
| 0–20 | 极度避险 | 资金全面涌入银行/公用事业/国债，题材股暴跌，ST 板块暴跌 |
| 21–40 | 偏防御 | 红利/高股息占优，题材炒作降温，资金偏向确定性 |
| 41–60 | 中性 | 无明显的攻防偏好，各类资产表现均衡 |
| 61–80 | 偏进攻 | 题材股活跃，高 beta 方向跑赢，赚钱效应扩散，新股受到追捧 |
| 81–100 | 极度追逐 | 题材全面爆发，涨停板疯狂，不看估值只看故事，杠杆资金大增 |

**专业参考**：可参考 Wind 的"风险偏好指数"或路透的风险偏好指标，但这些是国内机构视角。建议同时关注两融余额变化方向和北向资金方向。

#### 交易难度 `trading_difficulty`（0=极难操作，100=极易操作）

参考维度：轮动速度 + 冲高回落频率 + 低开高走/高开低走 + 是否出现"一做就错"。

| 区间 | 标签 | 参考量化标准 |
|---|---|---|
| 0–20 | 极难操作 | 盘中剧烈波动，追高必套，低吸也套，当天买入当天亏损概率极高 |
| 21–40 | 偏难 | 板块快速轮动，持续性差，上午涨的下午回落，方向选择错误代价大 |
| 41–60 | 中性 | 正常轮动节奏，少数方向有持续性，操作需要一定的方向判断能力 |
| 61–80 | 偏易 | 主线清晰且持续，回调即机会，顺势操作成功率高 |
| 81–100 | 极易操作 | 主线持续大涨，回调极浅，持股不动即获厚利 |

> **关键区分**：赚钱效应 vs 交易难度——某个交易日可能半导体大涨 5% 但盘中冲高 8% 后大幅回落：赚钱效应中等（持有者赚了），但交易难度很高（追高者当天亏损严重）。

#### 市场一致性 `market_consistency`（0=极端分化，100=全面同涨同跌）

参考维度：宽基指数涨跌幅差异 + 行业板块涨跌幅分布 + 大小盘收益差 + 成长价值收益差。

| 区间 | 标签 | 参考量化标准 |
|---|---|---|
| 0–20 | 极端分化 | 指数间涨幅差 > 3%，行业首尾涨跌幅差 > 8%，大小盘风格极度撕裂 |
| 21–40 | 明显分化 | 指数间涨幅差 1.5–3%，行业首尾涨跌幅差 4–8%，存在明确的结构偏好 |
| 41–60 | 中性 | 指数间涨幅差 0.5–1.5%，行业涨跌各半 |
| 61–80 | 较强一致 | 多数指数同向波动，指数间涨幅差 < 0.5%，行业涨跌幅集中在 ±2% 以内 |
| 81–100 | 完全一致 | 全面普涨或全面普跌，所有宽基指数同向、所有行业同向 |

> **专业参考**：可参考 Wind 的"个股涨跌幅标准差"或"行业涨跌幅离散度"指标。简易判断：观察 5 个主要宽基指数（上证/深证/沪深300/中证500/创业板）的涨跌幅差异。

### 3.6 前端校验规则汇总

| 字段组 | 校验规则 | 触发时机 |
|---|---|---|
| 主观评分（5 个） | 整数 0–100，可留空 | 提交时 warning（非阻断），标记 `is_complete=false` |
| 市场阶段 | 必须从枚举中选择，不可自由输入 | 提交时 warning |
| 广度数据（5 个） | 整数 ≥0，`market_up + market_down + market_flat` 约等于全市场个股总数（A 股约 5000–5500 只），超出范围时 warning 但不阻断 | 失焦时 hint |
| 成交额 | 正数，超过 50000 亿或不足 500 亿时 hint（"确认数据无误？"） | 失焦时 hint |
| 北向资金 | 在 -300~300 亿范围内，超范围时 hint | 失焦时 hint |
| 风格枚举（3 个） | 必须从下拉框选择，不可自由输入 | 提交时 warning |
| 领涨/领跌行业 | 纯文本，建议逗号分隔，长度 ≤ 256。留空不阻断 | 失焦时 length check |
| 观察分区（10 个） | 纯文本，单区长度建议 ≤ 5000 字。留空不阻断 | 失焦时 length check |
| 标签 | 最多 10 个标签，超出时阻断 | 添加时硬阻断 |

> **设计原则**：除了标签数量上限外，所有校验均为 **warning/hint 级别**（软校验），不阻断保存。日志模块的核心价值在于"记录"而非"精确"，宁可接受不完美的数据也不妨碍记录意愿。

## 四、自动填充设计

### 4.1 填充时机

日志创建时（`POST /api/journal/entries`），系统在同一个事务/流程中自动执行填充。后续用户可通过 `POST /api/journal/entries/{id}/snapshot/refresh` 手动刷新快照。

### 4.2 填充数据来源映射

| 快照字段 | 数据来源 | 查询方式 |
|---|---|---|
| `close_price` | `index_daily_bar.close_price` | `WHERE trade_date = :date AND index_code = :code` |
| `change_pct` | `index_daily_bar` → 计算 `(close - prev_close) / prev_close * 100` | 同上 + 前一日 |
| `volume_ratio_20d` | `index_factor_value` | `WHERE trade_date = :date AND factor_id = 'volume_ratio_20d'` |
| `return_5d/20d/60d/120d` | `index_factor_value` | `factor_id IN ('return_5d', 'return_20d', 'return_60d', 'return_120d')` |
| `ma_*_deviation` | 计算：`(close - ma_value) / ma_value * 100` | `index_factor_value` 中的 `ma_5d`/`ma_10d`/`ma_20d`/`ma_60d` |
| `volatility_20d` | `index_factor_value` | `factor_id = 'volatility_20d'` |
| `max_drawdown_60d` | `index_factor_value` | `factor_id = 'max_drawdown_60d'` |

### 4.3 填充范围

- 从 `benchmark_index` 中查询 `is_active = True` 的指数
- 对每个指数依次查询上述数据
- 数据缺失时，对应字段留 `NULL`（不阻塞日志创建）

### 4.4 快照刷新

用户可手动触发刷新（如系统数据回填后）。刷新时**覆盖更新**已有快照数据，但仅限自动填充字段，手动录入字段不受影响。

### 4.5 伪代码

```python
def build_index_snapshots(db: Session, trade_date: date) -> list[dict]:
    """为指定交易日构建所有活跃指数的行情与技术指标快照。"""
    indices = db.query(BenchmarkIndexModel).filter_by(is_active=True).all()
    snapshots = []
    for idx in indices:
        bar = _get_latest_bar(db, idx.index_code, trade_date)
        factors = _get_factors(db, idx.index_code, trade_date, REQUIRED_FACTOR_IDS)
        if bar is None:
            continue  # 该指数当日无数据，跳过
        snapshots.append(_assemble_snapshot(idx, bar, factors))
    return snapshots
```

### 6.4 关键交互流程

#### 流程 1：从日历创建日志

```
用户点击日历日期
  → GET /api/journal/calendar?year=&month= 返回 has_entry=false
  → 检测到无日志 → 显示"创建日志"按钮
  → 用户点击创建
  → POST /api/journal/entries { trade_date }
  → 自动填充快照 → 创建空观察分区
  → 跳转到 /journal/:entryId
  → 用户开始填写
```

#### 流程 2：当日快速录入

```
用户导航到 DashboardPage 或 JournalCalendarPage
  → 看到"今日日志"入口（突出显示当日日期）
  → 点击进入 /journal/date/2026-06-17
  → 如已有日志 → 直接加载
  → 如无日志 → 自动创建（减少一步点击）
  → 填写主观评分（5 个滑块，< 1 分钟）
  → 填写市场数据（2-3 分钟）
  → 填写关键观察分区（5-10 分钟）
  → 保存（可多次保存，不要求一次填完）
```

#### 流程 3：AI 分析触发

```
用户完成日志核心内容（评分 + 市场数据 + 观察）
  → 切换到 "AI 分析" Tab
  → 点击 "生成 AI 分析"
  → POST /api/journal/entries/{id}/ai-analysis
  → 显示 "分析中..." 状态（轮询 GET .../ai-analysis）
  → 分析完成 → 展示结构化结果
  → 用户可对 AI 结果进行编辑（作为观察内容的一部分）
```

### 7.4 错误处理

| 场景 | 处理方式 |
|---|---|
| LLM 未配置（api_key 为空） | 返回 400 "AI 分析功能未启用，请在 .env 中配置 LLM_API_KEY" |
| API 超时 | 重试 1 次，仍失败则 `status=failed`，记录 `error_message` |
| API 返回错误 | 不重试，`status=failed`，记录 HTTP 状态码和错误信息 |
| 响应 JSON 解析失败 | 尝试从 `raw_response` 中提取 JSON 子串，失败则 `status=failed` |
| 后台任务异常 | 最外层 try/except 兜底，写入 `error_message` |
