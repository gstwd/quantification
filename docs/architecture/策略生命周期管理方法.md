# 量化策略生命周期管理方法

> 本文是生命周期方法论，不是当前 API、状态机或自动化行为的契约。当前实现以《策略稳健性评估与生命周期监控实施说明》为准；系统不执行交易，也不会自动调参或变更生命周期状态。

## 1. 文档目的

量化策略不存在永久有效的保证。

即使一个策略已经通过历史回测、样本外测试、Walk Forward，并且在上线初期表现良好，也仍可能随着时间推移出现：

- Alpha 衰减
- 因子有效性下降
- 市场环境变化
- 策略拥挤
- 风格切换
- 交易逻辑失效
- 数据特征变化
- 随机回撤长期化

因此，量化系统不应采用：

> 研究 → 回测 → 上线 → 永久运行

而应建立完整的策略生命周期：

> 研究 → 验证 → 模拟 → 小资金 → 正式运行 → 持续监控 → 诊断 → 降权 / 调整 / 替换 / 退役

策略生命周期管理的核心目标不是寻找“永久有效”的策略，而是：

> 尽可能早地区分正常波动、暂时失配和真正失效，并在策略失效时有序处理。

---

# 2. 核心认知

## 2.1 过拟合与 Alpha Decay 是两类不同问题

### 过拟合

过拟合发生在策略研发阶段。

典型表现：

```text
样本内表现很好
↓
样本外明显恶化
↓
实盘很快崩溃
```

主要原因包括：

- 参数搜索过多
- 因子组合过多
- 反复查看测试集
- 根据历史最优结果不断增加条件
- 使用复杂模型拟合噪声

过拟合的主要解决方式：

- 简化模型
- 限制参数自由度
- IS / OOS
- Walk Forward
- 参数稳定性
- 参数高原
- 粗粒度参数
- 因子删减实验
- 更严格的策略验证

---

### Alpha Decay

Alpha Decay 发生在策略原本真实有效之后。

典型表现：

```text
历史有效
↓
样本外也有效
↓
实盘初期有效
↓
Alpha / IC / IR 随时间逐渐下降
```

Alpha Decay 不是证明策略当初是假的。

它意味着：

> 原本存在的统计优势正在变弱。

因此：

```text
过拟合 → 研发流程问题
Alpha Decay → 生命周期问题
```

两者必须分开处理。

---

# 3. Alpha 为什么会衰减

可以将策略失效原因粗略划分为以下几类。

## 3.1 Market Learning

市场参与者逐渐发现并使用同类信号。

结果：

```text
发现者增加
↓
交易行为趋同
↓
价格更快反映信息
↓
原始 Alpha 被压缩
```

对于：

- 动量
- 简单技术信号
- 公开因子
- 容易复制的规则

尤其需要关注。

---

## 3.2 Crowding

越来越多资金交易相似方向。

可能表现为：

- 因子收益波动增加
- 同类股票相关性上升
- 回撤同步化
- 策略收益变得更加极端
- Alpha 长期下降

对于个人量化，不建议一开始建立复杂的拥挤度预测模型。

优先监控简单指标：

```text
Factor Return Decay
Factor IC Decay
Factor Volatility
Pairwise Correlation
Turnover
```

拥挤度主要作为：

> 风险诊断指标

而不是直接用于高频调仓或因子择时。

---

## 3.3 Regime Change

市场环境发生变化，但策略逻辑没有变化。

例如：

```text
趋势市场
→ 趋势策略有效

震荡市场
→ 趋势策略频繁亏损
```

或者：

```text
低波动环境
→ 某策略有效

高波动环境
→ 策略表现恶化
```

Regime Change 不一定意味着永久失效。

因此：

> 亏损 ≠ 策略死亡

需要进一步判断：

```text
当前市场是否只是进入该策略历史上的弱势环境？
```

---

## 3.4 Alpha 本身消失

如果出现：

- 因子 IC 长期接近 0
- Rank Decay 消失
- 超额收益长期消失
- 参数稳定区域整体失效
- 不同市场阶段均失效

则更接近：

> 原策略的统计优势已经消失。

此时继续通过增加过滤条件“修复”策略往往容易产生新的过拟合。

---

# 4. 生命周期管理的核心原则

## 4.1 策略正式上线后尽量冻结

例如：

```text
strategy_v1.0

Momentum Lookback = 60
TopN = 10
Trend MA = 120
Max Exposure = 80%
Rebalance = Monthly
```

正式运行后：

- 不因为连续亏损两个月修改参数
- 不因为其他基金最近表现更好修改策略
- 不因为最近 90 日参数回测更优就替换 60 日
- 不因为增加一个过滤条件改善近期表现就立即上线

否则：

> 最新数据会被重新用于拟合。

运行期的第一目标应当是：

> 判断策略是否仍运行在合理统计范围内。

而不是：

> 持续寻找最近最优参数。

---

# 5. 生命周期状态设计

建议每个策略具有明确状态：

```text
RESEARCH
BACKTEST
OOS
PAPER
LIVE_SMALL
LIVE
WATCH
WARNING
SUSPENDED
SHADOW
RETIRED
```

典型生命周期：

```text
Research
   ↓
Backtest
   ↓
OOS
   ↓
Paper
   ↓
Live Small
   ↓
Live
   ↓
────────────────────
│                  │
Healthy          Warning
                   ↓
                 Review
             ┌─────┴─────┐
             ↓           ↓
          Resume       Reduce Risk
                         ↓
                      Shadow
                         ↓
                 Resume / Retire
```

# 6. 监控周期

建议个人中低频策略采用：

| 周期 | 主要任务 | 是否调整策略 |
|---|---|---|
| 每日 | 数据、信号、持仓、异常检查 | 不调整 |
| 每周 | 收益异常、执行异常检查 | 不调整 |
| 每月 | 策略健康监控 | 原则上不调整 |
| 每季度 | Strategy Review | 通常不调整 |
| 每半年 | 加入新数据重新评估 | 可以产生 Challenger |
| 每年 | 完整重新研究 | 可以升级版本 |
| 条件触发 | 重大异常或结构变化 | 随时 Review |

关键原则：

> 定期评估 ≠ 定期修改参数。

---

# 7. 每日 / 每周监控

这一层主要检查：

> 系统是否正常运行。

包括：

## 数据

- 行情缺失
- 复权异常
- 基本面字段异常
- 时间戳错误
- 数据更新失败

## 信号

- 信号未产生
- 信号数量异常
- 排名分布异常
- 策略暴露异常

## 持仓

- 理论仓位与实际仓位偏差
- 异常空仓
- 异常集中
- 风控未执行

这一层一般不用于策略调整。

---

# 8. 每月策略健康监控

建议系统自动生成：

```text
Strategy Health Report
```

---

## 8.1 收益

至少包括：

```text
1M Return
3M Rolling Return
6M Rolling Return
12M Rolling Return
Cumulative Return
Benchmark Return
Excess Return
```

---

## 8.2 回撤

包括：

```text
Current Drawdown
Max Drawdown
Drawdown Duration
Historical Drawdown Percentile
```

重点不是：

> 当前是否亏损。

而是：

> 当前亏损是否已经超出历史正常范围。

---

## 8.3 Rolling Sharpe / IR

监控：

```text
3M
6M
12M
24M
```

核心看：

> 是否存在持续性、单调性恶化。

不要因为某一个窗口突然下降就判断失效。

---

## 8.4 Rolling Alpha

至少计算：

```text
Strategy Return - Benchmark Return
```

并监控：

```text
3M Alpha
6M Alpha
12M Alpha
24M Alpha
```

---

# 9. Alpha Decay Monitor

建议在普通健康监控之外，新增：

```text
Alpha Decay Monitor
```

核心思想：

> 比较近期策略有效性与长期有效性。

---

## 9.1 Alpha Decay

例如：

```text
Recent Alpha = 最近 3 个月
Long Alpha   = 最近 12 / 24 个月
```

可以构造：

```text
Alpha Decay Score
=
(Recent Alpha - Long Alpha)
/
Historical Alpha Volatility
```

目的不是精确预测策略还能活多久。

而是检测：

> 最近 Alpha 是否显著低于长期状态。

---

## 9.2 IC Decay

因子策略重点监控：

```text
Recent IC
vs
Long-term IC
```

例如：

```text
历史 Rank IC = 0.04
过去 12M = 0.025
过去 6M = 0.010
过去 3M = -0.005
```

比单纯看净值更值得关注。

---

## 9.3 Decay 趋势

系统重点识别：

```text
一次下降
```

和：

```text
连续多个窗口单调下降
```

后者风险更高。

---

# 10. 因子策略监控

多因子策略不能只看最终组合收益。

至少应监控：

## Rank IC

```text
Momentum IC
Quality IC
Value IC
Size IC
```

---

## ICIR

衡量 IC 的稳定程度。

---

## Rank Decay

例如：

| Rank | 后续平均超额收益 |
|---|---:|
| 1-5 | +2.5% |
| 6-10 | +1.8% |
| 11-20 | +1.0% |
| 21-50 | +0.4% |
| 其他 | 0% |

如果：

> 排名与未来收益之间长期不再具有单调关系

需要重点调查。

---

## Factor Exposure

监控策略是否逐渐变成：

```text
Momentum
Value
Size
Quality
```

某个单一公开因子的高暴露组合。

但：

> 与公开因子相关性提高不能直接作为退役标准。

更合理的是进一步判断：

```text
扣除公开因子暴露后
是否仍存在稳定 Alpha
```

---

# 11. Strategy Expectation Gap

建议用：

> 历史分布

而不是简单固定阈值判断异常。

例如历史 Walk Forward 中：

```text
12M Alpha Distribution

P50 = 8%
P25 = 4%
P10 = 0%
P5  = -3%
```

现在：

```text
12M Alpha = -1%
```

虽然差，但仍可能属于历史合理范围。

如果：

```text
12M Alpha = -9%
```

则已经明显偏离历史经验。

因此建议监控：

```text
Current DD Percentile
Rolling Alpha Percentile
Rolling Sharpe Percentile
IC Percentile
Factor Return Percentile
```

定义：

```text
Expectation Gap
=
Actual Performance
-
Expected Historical Distribution
```

策略生命周期监控应尽量使用：

> 分布 + 分位数

而不是简单：

```text
Sharpe < 0
→ 死亡
```

---

# 12. 每季度 Strategy Review

季度 Review 的目标不是调参数。

而是回答：

> 策略为什么变差？

---

## 12.1 正常回撤

特征：

- 当前表现仍处于历史分布
- 因子 IC 基本正常
- Rank Decay 正常
- Alpha 没有明显持续衰减

动作：

```text
KEEP
```

---

## 12.2 Regime Mismatch

特征：

- 当前市场环境属于策略历史弱势阶段
- 策略行为与历史弱势环境一致
- 因子本身仍有一定预测能力

动作：

```text
KEEP
或
REDUCE_RISK
```

---

## 12.3 Alpha Decay

特征：

```text
Rolling Alpha ↓
Rank IC ↓
Factor Return ↓
```

并且多个时间窗口呈持续性下降。

动作：

```text
WATCH
↓
RESEARCH
↓
CHALLENGER
```

---

## 12.4 Crowding Risk

特征可能包括：

- 因子收益波动上升
- 组合内相关性提高
- 同类策略表现同步化
- 极端反转增加

个人系统中暂时把 Crowding 作为：

> 辅助诊断信息

不建议直接建立复杂 Crowding Timing 模型。

---

## 12.5 Strategy Failure

特征：

- Alpha 长期消失
- IC 长期接近 0
- Rank Decay 消失
- 参数稳定区域整体恶化
- 不同市场阶段均没有改善
- 原始投资逻辑不再成立

动作：

```text
SUSPEND
或
SHADOW
或
RETIRE
```

---

# 13. 失效诊断树

推荐系统使用：

```text
策略表现恶化
      ↓
是否超过历史正常波动？
      │
   否 ───→ KEEP
      │
     是
      ↓
底层因子是否仍有效？
      │
   是 ───→ Regime / Random Drawdown
      │
     否
      ↓
是否存在持续 Alpha / IC Decay？
      │
   否 ───→ WATCH
      │
     是
      ↓
原始经济逻辑是否仍成立？
      │
   是 ───→ RESEARCH / CHALLENGER
      │
     否
      ↓
RETIRE
```

---

# 14. 调整优先级

运行期调整建议按照以下优先级：

```text
风险
>
执行
>
参数
>
因子
>
核心逻辑
```

---

# 15. Level 0：保持不变

适用于：

- 当前波动处于历史合理范围
- Alpha 没有明显持续下降
- 因子正常
- 参数稳定
- 原始逻辑未改变

动作：

```text
KEEP RUNNING
```

这是最常见的状态。

---

# 16. Level 1：调整风险

优先于修改策略。

例如：

```text
Max Exposure
80% → 60%
```

或者：

```text
Single Position Limit
10% → 7%
```

特点：

> 不修改 Alpha 模型，只修改风险暴露。

适合：

- 当前环境不利
- 不确定性增加
- 策略进入 WATCH
- 尚未确认永久失效

---

# 17. Level 2：参数调整

例如：

```text
Lookback
60 → 90
```

必须非常谨慎。

调整依据不应是：

```text
最近两年 90 日参数收益更高
```

而应该是：

> 整个参数稳定区域发生系统性迁移。

例如：

```text
历史：
40~100 日整体有效

近期：
80~140 日整体稳定
40~60 日持续明显恶化
```

此时才可以产生：

```text
strategy_v1.1_candidate
```

而不是直接替换生产参数。

---

# 18. Level 3：因子结构调整

例如原策略：

```text
Score =
Momentum
+ Quality
+ Value
```

经过长期重新研究发现：

```text
Momentum → 仍有效
Quality  → 仍有效
Value    → IC 长期接近 0
```

可以产生候选策略：

```text
Score =
Momentum
+ Quality
```

但应当重新经过：

```text
Backtest
↓
OOS
↓
Walk Forward
↓
Paper
↓
Live Small
```

不能直接修改正式实盘策略。

---

# 19. Level 4：策略重构

如果发生：

- 核心市场机制变化
- 原经济逻辑不成立
- 因子关系发生结构变化
- 核心风险结构变化

应该视为：

```text
strategy_v2.0
```

即：

> 新策略

而不是普通调参。

---

# 20. Level 5：策略退役

不要假设所有策略都值得修。

适合退役的情况：

```text
因子 IC 长期≈0
+
Alpha 长期消失
+
Rank Decay 消失
+
多个 Regime 均无法恢复
+
原经济逻辑不再成立
```

此时应该：

```text
RETIRED
```

而不是继续：

```text
加入过滤条件
↓
重新找参数
↓
把历史重新拟合漂亮
```

---

# 21. 失效标准必须提前定义

避免运行后主观解释。

常见心理过程：

```text
赚钱
→ 策略有效

亏损
→ 正常回撤

继续亏
→ 市场风格不适合

严重亏损
→ 再等等
```

因此在上线前必须定义：

```text
Strategy Validity Rules
```

---

# 22. 推荐的失效触发规则

具体阈值必须来自：

> 策略自己的历史分布

而不是照搬固定数字。

可以设计：

---

## Drawdown Trigger

```text
Current DD
>
Historical DD 99th Percentile
```

进入：

```text
WARNING
```

---

## Alpha Trigger

```text
Rolling 12M Alpha
<
Historical 5th Percentile
```

持续多个观察周期后：

```text
REVIEW
```

---

## IC Trigger

```text
Rolling IC <= 0
```

持续较长周期后：

```text
WATCH / WARNING
```

---

## Decay Trigger

如果：

```text
3M Alpha < 6M Alpha < 12M Alpha
```

同时：

```text
3M IC < 6M IC < 12M IC
```

并持续多个窗口：

```text
ALPHA_DECAY_WARNING
```

---

## Structural Trigger

出现：

- 市场制度明显变化
- 数据定义变化
- 核心策略逻辑对应的市场机制消失

则：

```text
IMMEDIATE_REVIEW
```

不等待固定周期。

---

# 23. Champion / Challenger

正式运行版本：

```text
Champion
```

候选版本：

```text
Challenger
```

例如：

```text
Champion
strategy_v1.0

Challenger
strategy_v1.1_candidate
strategy_v2.0_candidate
```

---

## Challenger 的来源

可以来自：

- 参数稳定区迁移
- 删除失效因子
- 新增真正互补因子
- 新的风险控制方式
- 新的策略逻辑

---

## Challenger 不能直接替换 Champion

推荐流程：

```text
Research
↓
Backtest
↓
OOS
↓
Walk Forward
↓
Paper / Shadow
↓
Live Small
↓
Compare
↓
Promote / Reject
```

---

# 24. Shadow Mode

当某策略出现严重异常但尚不能确认永久失效时：

```text
LIVE
↓
SHADOW
```

Shadow 状态：

- 继续接收实时数据
- 继续产生交易信号
- 不实际下单
- 继续记录模拟收益
- 继续计算 Alpha / IC / Rank Decay

作用：

> 区分暂时性环境问题与真正长期失效。

之后：

```text
恢复 → LIVE
```

或：

```text
确认失效 → RETIRED
```

---

# 25. Stable + Experimental 架构

个人量化账户不建议所有资金持续追逐最新研究。

长期更合理的是：

```text
Stable Strategies
+
Experimental Strategies
```

例如：

```text
Stable
70%~90%

Experimental
10%~30%
```

Stable：

- 已充分验证
- 参数冻结
- 更新频率低
- 承担主要资金

Experimental：

- 新策略
- 新因子
- Challenger
- 小资金验证

这样可以避免：

# 35. 最终原则

策略生命周期管理不是：

> 不断修改策略，让它适应最近的数据。

而是：

> 尽可能判断策略现在发生了什么。

优先遵循：

```text
先监控
后诊断

先判断正常回撤
再判断失效

先调整风险
后调整模型

先产生 Challenger
再替换 Champion

先进入 Shadow
再决定 Retire

允许策略死亡
不要无限修复
```

最重要的是：

> 不追求单个策略永生。

真正应该长期建设的是：

> 一个能够持续研究、验证、运行、监控、诊断、降权、替换和淘汰策略的系统。
