# 参数化因子与参数高原治理升级方案

## 1. 升级结论

本次升级将策略系统从“固定参数因子 + 因子权重调节”升级为“因子模板 + 策略别名参数 + 参数高原研究”的架构。

- `mainline_rs_rotation_v12` 是唯一需要迁移到新架构的策略；不迁移其他历史策略、历史因子配置、回测或研究记录。
- 指数日线、估值、宏观、行业及成分等外部数据集继续保留，作为运行和研究的原始输入。
- 系统现有全部因子统一改造成因子模板：同一计算逻辑只登记一个模板，周期/窗口/比例等可调数值全部具备参数定义与校验（22 个模板可调参）；确实不含可调数值的 10 个模板采用同一模板接口，参数集为空。
- 删除 `index_factor_value` 表及其读写链路。实时策略分配、因子详情、回测、稳健性扫描和参数高原研究一律按当次配置从原始数据批量现算。
- 参数搜索目标不是挑选单一尖峰最优值，而是在研究期寻找跨窗口、跨成本假设仍稳定的参数高原；上线后仅允许人工基于监控信号在高原内调整旋钮。

本方案不引入因子世代、输入快照世代、值就绪记录、历史兼容层、因子值缓存或历史缓存迁移。它们对“只迁 v12、全部现算”的范围没有必要，反而会增加系统复杂度。

## 2. 现状核对与取舍

### 2.1 `index_factor_value` 的实际用途

经代码链路核对，该表并非只服务于因子详情页：

```text
实时策略分配
StrategyDecisionService
  → ContextBuilder（实时模式）
  → FactorProvider.load_asset_factors / load_market_factors
  → index_factor_value
  → StrategyEngine
```

实时模式下，`ensure_live_factors()` 还会根据缺失情况发起补算任务。因此直接删除该表会使实时分配每次都在请求链路中计算全部因子，既增加延迟，也会让缺失数据和计算失败更难观察。

回测路径不同：`FactorProvider.precompute_backtest_factors()` 基于已加载的原始数据批量计算，回测并不读取 `index_factor_value`。参数扫描也应沿用这个路径。

### 2.2 最终取舍：统一现算并删除表

当前表同时服务实时分配、详情页和补算任务，但这只是既有缓存架构的结果，不是业务必需。系统是日频指数策略，资产数量与单次请求的计算量有限；只要请求内先批量预加载原始数据、按模板实例批量计算并复用中间序列，实时现算的延迟可控。

目标链路统一为：

```text
实时策略分配 / 因子详情 / 回测 / 参数扫描
  → 预加载本次所需的原始数据
  → 模板工厂按规范化参数创建计算器
  → 批量计算因子值并在本次执行上下文复用
  → 策略引擎或详情响应
```

因此删除 `index_factor_value`、`IndexFactorValueRepository`、因子值写入门禁、实时缺失补算任务，以及所有缓存失效/重建逻辑。缺失语义改为“模板不存在、原始数据不足、计算失败”，不再存在“尚未缓存/尚未计算”。

研究结果以“当时的策略版本、模板版本、参数、研究窗口和数据截止日”为实验记录；不保存也不依赖因子值表。

## 3. 不可突破的边界

- 研究期固定为 2016-01-01 至 2025-12-31；2026-01-01 起为验证期。研究优化不得使用验证期数据。
- 仅 A 股指数可成为策略资产；行业和个股只可作为因子内部输入。
- LIVE 策略不自动调参、不自动替换参数。参数调整必须由人工发起，并留存研究、验证、审批和上线记录。
- 本次迁移只处理 `mainline_rs_rotation_v12`。其他历史策略、因子值、回测、优化会话和报告无需兼容；外部原始数据集不在清理范围。
- 新架构启用后产生的每一次研究扫描都必须计入试验台账，避免同一研究期无限试参。

## 4. 目标架构

### 4.1 因子模板

一个模板描述“如何计算一类因子”，而不是“某一个固定参数的因子”。模板最少包含：

```python
FactorTemplate(
    id="sma",
    version="1.0.0",
    display_name="简单移动平均线",
    parameter_schema={"period": {"type": "integer", "min": 2, "max": 250}},
    default_params={"period": 20},
    required_data=("index_daily_bar",),
    create_computer=...,
)
```

模板负责：参数默认值合并、类型/范围/组合校验、参数规范化、计算器实例化、所需回看窗口推导和版本声明。

`factor_definition` 继续作为模板目录：一条记录对应一个模板，`factor_id` 即模板 ID，不再为 `ma_5`、`ma_10` 等固定参数分别注册定义。保留现有表可减少不必要的数据库结构变动；同步逻辑改为同步模板元数据。

### 4.2 全量因子模板化

所有当前内置因子必须接入 `FactorTemplate` 注册表和统一工厂，禁止策略引擎按旧的固定因子 ID 分支处理。

- 同一计算逻辑只登记**一个**模板：周期、窗口、比例等可调数值一律声明为 `parameter_schema`，模板 ID 不携带具体参数取值；只有确实不含可调数值的模板才零参数。
- 后续改造某个因子时，只扩展其 `parameter_schema` 与计算器，不改变策略配置、现算执行接口、研究 API 和优化闭环。

当前模板目录共 32 个模板，其中 22 个可调参：

| 模板 | 参数 | 类型/范围/默认值 | 说明 |
| --- | --- | --- | --- |
| `sma` | `period` | 整数 2–250，默认 20 | N 日简单均线 |
| `return` | `period` | 整数 1–250，默认 20 | N 日累计收益 |

| `donchian_low` | `period` | 整数 2–250，默认 20 | Donchian 下轨 |

所有模板都要声明 `lookback_days(params)`；上下文构建器按本次策略实际参数取最大回看窗口，而不是按注册表中预设的固定窗口取数。**参数取值范围必须保证任一合法组合的回望不超过回测固定加载窗口（`BacktestService._get_lookback_days()`，默认口径最大值 730 天）**，该不变量由单元测试守护。

### 4.3 策略中的因子别名

同一模板可在同一策略中以不同参数多次出现。策略配置用“别名”承载策略语义，用模板 ID 和参数承载计算语义：

```json
{
  "alias": "trend_fast",
  "template_id": "sma",
  "params": {"period": 10},
  "transform": "trend_score",
  "weight": 0.35
}
```

配置校验顺序为：模板存在且启用 → 参数与模板模式匹配 → 合并默认值 → 规范化参数 → transform 合法 → 别名在本策略中唯一。

评分、过滤和择时配置引用 `alias`，而非固定因子 ID。输出中同时展示别名、模板、规范化参数和模板版本，保证研究报告可读。

### 4.4 参数的规范化与执行身份

参数对象必须以模板定义的默认值补齐、剔除未知字段、校验类型范围，并序列化为稳定的规范 JSON。规范化参数与模板版本共同构成本次计算实例的身份，用于请求内中间结果复用、任务去重和实验审计。

这里不需要 `params_hash`、因子世代或持久化缓存键。改变模板版本或参数只会创建新的运行实例；旧因子值不保留也无需兼容。

## 5. 统一现算执行路径

### 5.1 执行上下文与复用

每次实时分配、详情查询或研究任务都构建一个只读执行上下文：先按策略实际参数推导最大回看窗口，再一次性加载所需指数日线、估值、宏观及面板输入。`FactorProvider` 不再查询数据库中的因子值，而是协调模板计算器对这些输入批量计算。

同一次执行中，以“模板 ID + 模板版本 + 规范化参数 + 数据日期范围”为键保存内存中间结果；多个别名引用相同模板参数时只计算一次。该复用仅限当前请求或当前后台任务生命周期，任务结束即释放，不持久化。

### 5.2 实时分配与因子详情

1. 解析策略别名，规范化模板参数。
2. 根据所有模板参数加载足够的原始数据，并批量计算资产因子和市场因子。
3. 将结果交给策略引擎；因子详情页调用同一计算入口返回截面或时间序列。
4. 原始数据不足、模板未知或计算异常时，返回结构化原因并禁止把不完整结果伪装为有效分配。

实时路径不写数据库、不入队补算，也不维护缓存失效任务。原始数据补拉或订正后，下一次请求自然基于新数据计算。

### 5.3 回测与研究

回测、候选比较、参数扫描、稳健性和消融测试使用与实时相同的模板计算接口，但在任务开始时预加载完整研究区间数据，在任务内复用基础行情和中间序列。所有场景均不读写 `index_factor_value`。

结果必须记录模板版本、规范化参数、研究窗口、数据截止日、成本假设和执行日历。这样保证“运行了什么”可审计，而无需保存任一历史因子值。

## 6. `mainline_rs_rotation_v12` 迁移

新建 v12 的新架构版本，而不是修改历史记录。迁移只做配置与验证，不迁旧因子缓存、回测或优化档案：

1. 冻结当前 v12 配置并导出只读备份。
2. 将其中所有固定因子映射成模板引用、别名和显式参数。
3. 使用相同研究期和原始数据跑一次旧/新配置对照；没有改变参数语义的条目，结果应在数值容差内一致。
4. 为新版本创建独立策略修订记录，作为后续研究与上线的基线。
5. 在研究期完成首轮参数高原扫描；通过验证期人工验收后，才可提升为 LIVE 候选。
6. 旧 v12 保留为只读历史基线；若新版本未验收，不替换线上策略。

新策略修订需要不可变快照：策略配置、每个别名的模板 ID/版本/规范化参数、研究窗口、数据截止日和运行口径。这里的快照用于说明一次实验“运行了什么”，不要求保存旧因子值或建立因子世代。

## 7. 参数搜索与参数高原

### 7.1 搜索单位

一次研究任务只允许围绕一个明确假设调整少量旋钮。例如：

```text
假设：v12 的趋势确认周期位于 8–18 日时，能改善风险调整后收益，且不会使换手显著恶化。
参数：trend_fast.period = [8, 10, 12, 14, 16, 18]
其余配置：完全冻结
```

禁止在同一批次同时枚举大量因子、权重、过滤阈值和调仓规则。多维搜索必须预先登记范围、组合数、停止规则和评价指标。

### 7.2 高原判定

单参数候选按参数排序形成序列；二维及以上候选按参数网格形成连通区域。一个参数值或区域可进入高原候选，至少应满足：

- 与全样本最佳候选相比，主目标指标达到预设相对阈值（默认不低于最佳值的 90%，具体阈值按指标定义）；
- 至少有连续 3 个相邻合法参数值，或二维网格中存在连续相邻区域；
- 在滚动样本外窗口中大多数窗口不显著劣于基线；
- 成本阶梯、最大回撤、换手率和收益集中度未触发硬性风控门槛；
- 参数越界、原始数据不足或计算失败的点不得被当作低表现点连接进高原。

系统应同时报告“高原”与“尖峰”：最优点若明显优于邻近点但没有连续稳健邻域，只能标为尖峰候选，不能直接作为上线参数。

### 7.3 参数旋钮

通过验收的高原必须定义运行边界：中心参数、可操作上下界、允许步长、适用市场状态、监控指标和触发人工复核的条件。

上线后，监控只提供建议，例如“当前参数接近高原边界且近 3 个再平衡周期表现退化”。系统不得自行换成邻近参数。人工决定调整时，必须建立新策略修订、记录理由，并走研究/验证/审批流程。

## 8. 优化闭环与试验台账

优化会话增加参数研究类型：

```text
draft → parameter_scan → plateau_analysis → validation → accepted / rejected
```

每次扫描记录：基线修订、假设、模板版本、参数空间、实际执行候选数、失败/跳过原因、研究期分段结果、成本阶梯、选择规则、是否使用验证期及审批人。

候选数、重复尝试和中途扩展范围都计入新架构的试验台账。只有在研究期内选定的少量高原候选才可进入验证期；验证期数据一经消费即留痕，不能用其反复反向挑参。

## 9. 实施阶段

### P0：接口与配置模型

- 定义 `FactorTemplate`、参数模式、规范化器和模板注册表。
- 扩展策略配置为因子别名 + 模板 + 参数，并完成 API/CLI 校验。
- 为全部现有因子接入模板：同一计算逻辑只登记一个模板，可调数值全部收敛进 `parameter_schema`（22 个模板可调参），其余为零参数模板。

### P1：统一现算路径

- 改造 `FactorProvider`，使实时和回测都通过模板工厂按实际参数批量计算。
- 改造 `ContextBuilder`，按参数推导最大回看窗口并一次性预加载原始数据。
- 在请求/任务内实现计算实例与中间序列复用，避免同参别名或扫描候选重复计算。

### P2：移除因子值持久化

- 删除 `index_factor_value` 表、ORM 模型、仓储、外键/索引、迁移后的遗留代码和相关 API 查询。
- 删除 `FactorService` 的因子值写入职责、`ensure_live_factors()`、缺失补算任务及缓存失效/重建运维入口。
- 因子详情页改用统一现算入口；缺失诊断收敛为模板未知、原始数据不足或计算失败。

### P3：v12 迁移与对照

- 创建 `mainline_rs_rotation_v12` 的新架构修订。
- 完成固定因子到模板别名的映射与研究期回归对照。
- 仅在对照通过后，将其作为参数研究基线。

### P4：参数扫描、高原与生命周期

- 实现单参数、二维网格扫描和高原分析结果。
- 接入滚动样本外、成本阶梯、稳定性门槛与试验台账。
- 在策略详情和生命周期页面展示已批准旋钮及人工复核提示。

## 10. 验收标准

- 任意现有因子都能以统一模板接口注册、校验、计算和展示；不再存在引擎依赖的固定参数因子 ID，也不存在带周期后缀的重复模板。
- 22 个可调参模板的任意合法参数都能在策略配置、实时分配、因子详情、回测和扫描中端到端运行；非法参数在保存前被拒绝；任一合法参数组合的回望不超过回测固定加载窗口。
- 同一策略可同时使用同一模板的多个别名和不同参数，且评分/过滤引用无歧义。
- 实时分配和因子详情从原始数据现算，不产生因子值持久化、补算队列或缓存失效任务。
- `index_factor_value` 及其 ORM、仓储、API/任务依赖均被移除；回测及研究扫描可对同批参数复用原始数据与中间计算结果。
- `mainline_rs_rotation_v12` 的固定参数映射在不改变语义时通过研究期回归对照；其他历史策略无需迁移。
- 高原报告能区分高原、尖峰、无效点和数据不足点，包含窗口稳定性、成本敏感性、换手和回撤约束。
- LIVE 状态下没有任何自动调参路径；每次人工旋钮调整都有策略修订、验证使用记录和审批轨迹。
