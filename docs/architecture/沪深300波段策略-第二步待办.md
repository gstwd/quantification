# 沪深300波段策略 — 第二步待办

本文档记录策略完整实现所需的架构扩展项，当前系统暂不支持，需后续开发。

## 1. 月线数据聚合层

**需求**：策略核心的牛熊判断依赖月线级别信号（10月均线方向、月线收盘价与均线关系）。

**现状**：系统只有日线因子（`index_daily_bar` 表），无法直接计算月线级别的均线。

**实现方案**：
- 新增月线数据聚合服务：从日线 OHLC 聚合为月线 OHLC（取每月首个开盘价、最高/最低价、最后收盘价）
- 新增 `MonthlyBarComputer` 因子族：`monthly_ma_5m`（5月均线）、`monthly_ma_10m`（10月均线）
- 新增月线级别的动量因子：`monthly_return_2m`（近2月收益率）、`monthly_return_3m`（近3月动量）
- 存储方案：可新增 `index_monthly_bar` 表，或在因子层直接从日线实时聚合

**影响范围**：
- `factors/service.py` — `_load_context()` 需加载月线数据
- `factors/builtins/` — 新增 `monthly.py` 模块
- `infra/db/models/` — 可能新增 ORM 模型
- `alembic/` — 新增迁移

## 2. 市场宽度因子

**需求**：策略文档中的"市场宽度恶化"信号 — 沪深300成分股站上5月均线的比例持续下降。

**现状**：系统只处理指数级别数据（`index_daily_bar`），没有成分股级别的行情数据。

**实现方案**：
- 新增成分股数据源：从 AkShare 获取沪深300成分股列表及其日线行情
- 新增 `constituent_daily_bar` 表存储成分股日线
- 新增 `BreadthComputer` 因子：计算成分股站上 N 日均线的比例
- 因子 ID：`breadth_above_ma20`（站上20日均线比例，近似5月均线）

**影响范围**：
- `infra/clients/` — 新增成分股数据客户端
- `infra/db/models/` — 新增成分股行情表
- `factors/builtins/` — 新增 `breadth.py` 模块
- `services/ingest_service.py` — 新增成分股数据摄取
- `alembic/` — 新增迁移

## 3. 连续N月收阳判断

**需求**：熊市反弹确认条件 — "连续2个月收阳"。

**现状**：因子层只有日线数据，无法直接判断月线涨跌。

**实现方案**：
- 依赖"月线数据聚合层"（待办 1）
- 新增 `MonthlyStreakComputer` 因子：统计连续收阳/收阴月数
- 因子 ID：`monthly_up_streak`（连续收阳月数，正值）/ `monthly_down_streak`（连续收阴月数，负值）
- 在 Filter 中使用：`monthly_up_streak >= 2`

## 4. ERP 百分位

**需求**：策略文档中的"ERP > 80%历史分位"判断。

**现状**：第一步只实现了原始 ERP 值（`erp` 因子），百分位需要历史分布计算。

**实现方案**：
- 方案 A：在因子层新增 `erp_percentile` 因子，从 `index_factor_value` 表读取历史 ERP 值计算百分位
  - 需要 `FactorService` 支持"读取已有因子值作为另一个因子的输入"
  - 与现有 `pe_percentile`（由数据源直接提供）模式不同
- 方案 B：在回测引擎中通过时序数据后处理
  - 回测完成后，对 ERP 时序做百分位排名
  - 不修改因子层，但无法在实时模式中使用
- 方案 C：新增"派生因子"机制 — 因子 A 的值作为因子 B 的输入
  - 最通用但架构改动最大

**推荐**：先用方案 B（回测后处理），如需实时使用再实现方案 A。

## 5. 条件化策略逻辑

**需求**：牛市和熊市使用完全不同的买卖条件：
- 牛市买点：回调 >8% + 站上5月均线 + 2个月收益率转正
- 熊市买点：PE分位 <20% + 跌幅 >15% + 连续2月收阳

**现状**：引擎的 Score/Filter 模块对所有资产使用相同的因子和规则，不支持按 regime 切换逻辑。

**实现方案**：
- 方案 A：多策略模式 — 创建两个独立策略（牛市策略、熊市策略），由外部调度器根据 regime 选择执行哪个
- 方案 B：引擎支持条件分支 — `StrategyConfig` 新增 `regime_rules` 字段，不同 regime 使用不同的 score/filter 配置
  - 例：`{"offensive": {score: {...}, filters: {...}}, "defensive": {score: {...}, filters: {...}}}`
  - 引擎在 timing 评估后，根据 regime 选择对应的 score/filter 配置
- 方案 C：利用现有 Timing + 多因子组合 — 通过巧妙的因子权重设计，让同一套配置在不同市场环境下自然产生不同行为
  - 第一步已采用此方案，但精度有限

**推荐**：方案 B 最符合策略设计思想，但需要修改引擎核心。方案 A 最简单但管理成本高。
