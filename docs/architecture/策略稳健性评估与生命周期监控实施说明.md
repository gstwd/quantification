# 策略稳健性评估与生命周期监控实施说明

本文档说明系统如何落地两篇方法论文档的要求，以及具体的接口、默认值与使用方式。

- 理论来源 1：[个人量化策略_过拟合与因子研究方法论.md](个人量化策略_过拟合与因子研究方法论.md)
- 理论来源 2：[策略生命周期管理方法.md](策略生命周期管理方法.md)

核心原则（贯穿全部实现）：

1. **不自动调参**：系统只监控、计算、报警、生成报告，正式策略升级必须人工确认。
2. **不自动改状态**：生命周期状态（LIVE/SUSPENDED/RETIRED）只由人工变更。
3. **验证期只能否决**：2026-01-01 之后的数据不能用于确认有效性，看过后必须留痕。

## 1. 分层：单次回测 vs 候选集

方法论文档里的指标分成两类，实现上也分两层——因为 PBO、Deflated Sharpe 这类
指标必须知道"一共试过多少个候选"，单个回测不可能算出来。

| 层级 | 指标 | 位置 |
| --- | --- | --- |
| 单次回测 | 成本折算（毛/净双口径）、收益集中度、分段一致性、回撤结构、持仓集中度 | `domain/research/stability.py` → `BacktestDetail.stability` |
| 候选集 | CSCV-PBO、Deflated Sharpe、块自助法置信区间、参数邻域稳定度、因子消融、池扰动 | `domain/research/robustness.py` + `services/robustness_service.py` |
| 上线后 | 分位、期望差、诊断结论、建议动作 | `domain/research/lifecycle.py` + `services/strategy_lifecycle_service.py` |

### 为什么稳健性指标在读取路径现算

与分年度绩效表一致，`stability` 块由已落库的逐日结果（组合收益、基准收益、
单边换手、仓位、持仓）现算，**不新增数据库列、不重跑历史回测**，存量回测
立刻可用。指标输出内固定记录口径指纹（`cost_bps` / `execution_model` /
`data_quality_mode` / `benchmark_index_code`），避免不同口径的指标被相互比较
——历史上 warn/strict 口径分叉曾导致同一配置出现两套结果。

## 2. 成本口径

- 回测汇总仍是**毛收益口径**，净口径指标并列展示，默认单边成本 10bp
  （`QUANT_ETF_DEFAULT_COST_BPS`）。
- 折算公式：`净收益 = 毛收益 − 单边换手率 × cost_bps / 100`。
  系统的 `turnover` 字段是单边换手率（仓位变动绝对值之和 / 2）。
- 成本在**创建回测时固化**到 `params["_cost_bps"]`，保证同一回测在不同时点
  算出同样的净指标；可在创建时用 `cost_bps` 覆盖。

## 3. 研究期 / 验证期边界（硬约束）

- 研究期：`2016-01-01 ~ 2025-12-31`；验证期：`2026-01-01` 起。边界写在
  配置层（`Settings.research_period_start/research_period_end/validation_period_start`），
  规则实现在 `domain/research/periods.py`。
- `backtest_run` 新增 `purpose`（research/validation/monitor，默认 research）
  与 `purpose_reason`。
- **研究类回测/优化会话越过研究期末端会被直接拒绝**（HTTP 422 / CLI 报错）。
  验证与监控用途允许使用验证期数据，并写入留痕列表：
  `GET /api/backtests/validation-usage`。
- CLI 默认值随之调整：`backtest run` 与 `optimization start` 的 `--end` 缺省
  为研究期末端，避免"不带日期"的调用意外消费验证期数据。

## 4. 稳健性验证（robustness）

```bash
python -m quant_etf_api.cli robustness scan   --strategy <id> --windows 4
python -m quant_etf_api.cli robustness ablate --strategy <id> --windows 4
python -m quant_etf_api.cli robustness pool   --strategy <id> --windows 4 --samples 8
python -m quant_etf_api.cli robustness collect <robustness_id> --wait
python -m quant_etf_api.cli robustness stats   <robustness_id>
```

- 变体派生：`scan` 按配置数值叶子生成 ±1 档粗粒度扰动（比例类字段上限截到 1.0）；
  `ablate` 逐个移除评分因子与过滤条件（保留至少一个）；`pool` 生成随机 80% 子池、
  剔除常持指数、剔除后上市指数。
- **池扰动必须改写 `config_json.index_codes`**：策略自身的 index_codes 会覆盖
  回测请求的资产范围，用请求参数改池会得到静默错误的结果。
- 批次结果落库 `robustness_run`，`trial_count` 累加即 Deflated Sharpe 需要的
  试验次数台账（`stats --n-trials` 缺省取该值）。
- 全部批次固定在研究期内执行，不会消耗验证期数据。
- 扫描口径可审计：旋钮截断按业务重要性（择时阈值 → 过滤阈值 → 评分权重 →
  风险/仓位 → 调仓），支持 `--preset quick|standard`、`--knobs`、`--knobs-file`，
  实际口径落在 `robustness_run.scan_params`。
- 批量探索与正式验收分工（详见
  [回测流程问题与优化清单](回测流程问题与优化清单.md) D-1）：
  `cli research batch` 复用同一条执行路径但不落库（输出 `caliber.persisted=false`），
  用于快速筛掉没价值的想法；**报告与验收数字必须来自落库回测**。
- 变体草稿策略带 `is_variant` / `source_batch_id`，用
  `cli strategy prune-variants --batch <批次>` 清理（默认预演）；
  删除变体**不等于**抹掉试验次数台账，`robustness_run` 批次行必须保留。
- 验证期消费留痕写在策略元数据（`strategy_config.validation_consumed_at/note`）：
  只要创建过 `purpose=validation|monitor` 的回测就自动标记，人工可用
  `cli strategy consume-validation <策略> --note "..."` 补记；被标记后该策略的
  验证期证据只能用于否决。

## 5. 生命周期模块（上线后）

- 范围：只覆盖"人工标记上线之后"。策略创建与优化仍走既有体系，不重复建设。
- 状态与健康度分离：`lifecycle_status`（LIVE/SUSPENDED/RETIRED，仅人工变更）
  与 `health_level`（HEALTHY/WATCH/WARNING/CRITICAL，自动计算）。
- 上线（`POST /api/strategies/{id}/lifecycle/online`）会：
  1. 冻结当前配置快照与哈希；2. 复用或执行研究期回测；3. 生成研究期分布
  （1M/3M/6M/12M/24M 的超额与夏普分位表、逐日回撤分位表）。
- 刷新（`POST /api/strategies/{id}/lifecycle/refresh`）同步执行上线后回测
  （`purpose=monitor`），把表现填回研究期分布，输出分位、期望差、诊断与
  建议动作，并追加一条 `strategy_health_snapshot`。
- 诊断阈值全部取自该策略自身的研究期分布：回撤分位 > 95 → WARNING；
  3M 超额分位连续 2 次 < 5 → WATCH；
  3M<6M<12M 且**过半引用因子**的 IC 后半段显著低于前半段（差值 > 2 倍标准误）
  → ALPHA_DECAY；回撤极端叠加衰减 → CRITICAL。
- 指标包含净成本口径与策略引用因子的 Rank IC/ICIR：IC 每天产生一个横截面观测，
  是上线初期（样本不足以支撑收益类年化指标时）唯一具备统计功效的证据。
- IC 证据的两个硬约束：① 横截面指数数量少于 20 的交易日不产出有效 IC
  （指数池小的时候 Spearman 取值粒度极粗，n=3 时只能取 ±1/±0.5）；
  ② 衰减判定**按因子分别计算并做显著性检验**（前后半段差值 > 2 倍标准误），
  再由"过半引用因子显著衰减"给出顶层结论——不做跨因子池化，因为不同因子的
  符号与量级不同，池化均值的"衰减"没有因子级含义。
- 每个因子同时记录 `t_stat`（IC_IR × √有效样本数）与 `cross_section_n_avg`，
  体检表新增 t 值列：|t| < 2 时该因子的 IC 均值不应被当作证据使用。
- **LIVE 状态下禁止直接修改 `config_json`**（需先暂停，或走候选 promote 新版本），
  避免监控对象被静默替换。
- 前端：`/lifecycle` 页面（上线策略列表 + 体检详情 + 手动刷新）；策略中心卡片
  显示上线状态与健康等级。

## 6. 验收清单（优化会话）

`optimization finish --strict` 要求 7 项全部通过：

1. 验证窗平均夏普 ≥ 基线；
2. 平均最大回撤劣化 ≤ 2pct；
3. 夏普胜出折数 ≥ 50%；
4. 验证窗平均累计收益 ≥ 基线；
5. **净成本口径**验证窗平均夏普 ≥ 基线；
6. **参数邻域**无方向反转且处于平台（未跑 `robustness scan` 直接判不通过）；
7. **分段一致性**：剔除最好折后候选夏普仍不低于基线。

## 7. 明确不做

- 自动调参、自动状态迁移、"收益下降 → 自动重新优化 → 自动上线"闭环。
- SHADOW 状态：本系统不下单、只出信号，SHADOW 与 LIVE 行为无差异。
- 容量模型与拥挤度择时、实盘成本反事实校准（资金规模与数据积累到位后再考虑）。
- PIT 资产池重建：这是"切分研究期/验证期"解决不了的选择性偏差，仍需单独研究。
