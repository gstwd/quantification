使用规则：

## 已否决提议

- **调整第 8 项 Deflated Sharpe 门槛**（`acceptance_min_deflated_sharpe`）：不做，保持 0.95。2026-10-25 已经用 `research dsr-calibrate` 校准过：0.95 下假阳性率约为 0，要有 75% 的功效，年化超额夏普需要约 1.5；降到 0.90 时最坏情况的假阳性率约 3.9%。用户决定维持 0.95。重新评估条件：用户主动提出。
- **恢复因子值落库或缓存**（`index_factor_value`、因子值补算队列、缓存失效链路）：不做。因子值一律由原始数据现算，见 AGENTS.md「策略、因子与回测」。重新评估条件：某项具体研究因现算耗时无法完成，且已经排除计算实例复用不足这个原因。

以下六条由 AI 起草，用户于 2026-11-05 逐条确认：

- **按行数拆分大文件**（`services/backtest_service.py` 约 3200 行、`services/data_management_service.py` 约 3200 行、`cli.py` 约 2750 行、`services/strategy_config_service.py` 约 1500 行）：不做。行数本身不构成阻塞；拆分要改大量调用点和测试里对私有方法的打桩，回归风险高，又没有研究收益。重新评估条件：某个具体需求因文件结构无法安全完成。
- **合并或重命名按审查轮次命名的测试文件**（`test_f_*_fixes.py`、`test_*_review_fixes.py` 等）：不做。只是整理，没有行为收益，还会打断 git blame / log 追溯。新测试仍按被测模块命名（见编码规范「测试规范」）。重新评估条件：无。
- **把路由层直连 repository 的写法收敛进服务层**（`api/routers/` 下 `ai_factors`、`factors`、`indexes`、`industry`、`keyword_tags`、`market_data` 6 个文件，约 25 处）：存量保持原样，新增路由不得再直连。这条只靠文字约束，不进分层守卫。重新评估条件：出现事务或口径不一致的缺陷。
- **单独立项消除分层守卫的两条历史例外**（`factors/compute.py` → 面板服务、`services/robustness_service.py` → `cli_pool`）：不做。只有相关模块因具体需求必须修改时才一并处理，处理后从 `_KNOWN_EXCEPTIONS` 删除。
- **给 `expr` 派生因子增加截面函数**（`cs_rank`、`cs_zscore` 一类跨指数运算）：不做。截面标准化归评分层，由 `score.scoring_mode=rank|zscore` 完成；在因子表达式里再加一套会形成两处截面口径，而且截面值依赖当日候选池，会牵连口径指纹和预热期。重新评估条件：某个已登记的研究假设需要截面运算，且评分层的模式表达不了。
- **引入新的通用基础设施**（插件框架、统一配置中心、事件总线、依赖注入容器、import-linter、收紧现有 `[tool.mypy]` 配置）：不做。现有扩展点和测试守卫已经够用；现有 mypy 配置保持不变。重新评估条件：出现现有扩展点表达不了的具体需求。
