# 系统能力边界

配置策略时必须了解的约束。用户需求触及以下边界时，明确指出并给出替代方案；字段与校验规则以
`engine/config.py`、`strategy validate` 与 CLI `--help` 为准，全局边界见根目录 `AGENTS.md`。

## 资产与频率

1. **只研究 A 股指数**：策略资产只能是 `benchmark_index` 中用户维护、有实际 ETF 对应物的指数；申万行业与个股只作因子输入，
   不能进入 `index_codes` 或作为回测标的。不支持 ETF 本身、个股选股、债券 / 商品 / 跨境资产。
2. **只有日频**：没有分钟 / 小时数据；顶层 `frequency` 只是标注字段，调仓频率由 `rebalance` 两条腿各自设定
   （daily / weekly / biweekly / monthly）。
3. **只做多、无杠杆**：权重 ≥ 0，总仓位 ≤ 1；不能做空弱势资产，"对冲"只能用降低总仓位表达。
4. **不执行交易**：系统输出研究与配置结果，不下单、不管理账户。

## 选股与评分

5. **过滤只看单个资产**：每条规则比较同一资产的因子原值（`compare_to` 也是同一资产的两个因子），不能写"保留得分高于中位数
   的资产"这类跨资产条件。替代：`scoring_mode: rank` + `top_n`；"全部被过滤 = 空仓"可表达全局条件。
6. **操作符 7 种**：`gt / lt / gte / lte / eq / neq / between`，`between` 不支持 `compare_to`；规则组最多嵌套 3 层。
7. **评分是加权合成**：absolute 按 `Σ(|w| × d) / Σ|w|`，rank / zscore 先逐因子横截面标准化再加权。因子相乘、比值、非线性组合
   先用 `expr` 派生因子构造，再放进评分；派生因子没有截面函数。
8. **排序只按综合得分**：`rank.sort_by` 只有 `score`；要按某个因子排序就只用该因子评分。
9. **权重方法 5 种**：equal_weight、score_weight、winner_take_all、inverse_vol、risk_parity；不支持最小方差、均值方差、
   Black-Litterman。波动率目标、回撤止损、移动止损在 `risk` 叠加层。

## 数据

10. **估值覆盖有限**：乐咕乐股覆盖 12 个指数（PE 与 PB），其他中证系指数只有 PE，深证系等没有估值；行业 / 主题指数的估值因子
    常为空。
11. **回望上限**：任一参数组合的回望不超过回测行情预加载窗口（730 天）；`valuation_percentile` 单独扩展估值预加载；派生因子
    超限在校验期拒绝。
12. **OHLC 依赖**：`rsrs`、`price_position_ir`、`atr`、`donchian_*`、`low_amplitude_momentum` 需要最高 / 最低价，缺失的标的会被
    回测候选池剔除。
13. **择时代理**：择时因子按 `proxy_index_codes` / `factor_proxies` 指定的指数取值，代理必须有行情；市场级模板对所有指数同值。

## 研究流程

14. **组合策略**（`kind=composite`）不能做稳健性扫描、优化会话、研究批量与研究战役，成员也不能是组合策略。
15. **研究期边界**：研究用途只能用 2016-01-01 ~ 2025-12-31；验证期数据只能否决、使用即留痕（见 `AGENTS.md`）。
16. **上线后冻结**：LIVE 策略不能直接改配置，系统不会自动调参或自动上线。
